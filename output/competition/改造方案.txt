[Heading 1] 一、为什么现在必须停下来先想清楚
在动手补史料、改代码之前，需要先确认一个方向性问题：这款产品到底靠什么让 12–18 岁学生真正「学进去」？
当前版本的状态，可以概括为一句：它现在是一个「能看完的互动小说」，而不是一个「能让人学进去、还想回来的学习产品」。 具体表现在三个已确认的病灶上：
第一，AI 对话形同虚设。每个自由对话节点只要求问一轮就能点「继续剧情」，AI 的知识库每期只有 3–4 条示例史料，学生随便问两三个问题就词穷了。AI 扮演的不是「老师」，而是一个「可跳过的插曲」。
第二，台词量少、节奏单一。每个时期只有十几段旁白与台词，且全部是「看台词 → 选选项 → 继续看」的线性推进，学生全程是被动观众。
第三，学习效果不可度量、没有留存钩子。通关后只弹一句「共触发 N 个知识锚点」就结束，没有检验、没有回顾、没有产出，「我的」页里的学习报告和数据导出全是占位。
这三点的根源是同一个：产品把 AI 当成了「回答机器」，而不是「会追问、会考察、会给反馈的历史老师」。
本方案的核心主张一句话：把 AI 对话从「插曲」升级为「主线」，把学生从「观众」变成「探究者」。其余所有设计（史料、台词、交互、闭环）都围绕这一主张展开。

[Heading 2] 抓手一：把「线性看戏」改成「探究闭环」
每个时期不再是「看一堆台词」，而是围绕一个核心问题展开探究。四个时期各挂一个待解决的问题：
AI 的职责随之改变：不直接告诉答案，而是用苏格拉底式追问逼学生自己说出关键信息。例如在「读书壮游」时期：学生问「您七岁就写诗了吗？」，杜甫不直接答「对」，而是反问「你可知我祖父是谁？我的诗才，和他有何关系？」；学生答出「杜审言」，杜甫认可并推进、点亮「家世」锚点；答不上来，则用更小的台阶引导。这才叫「学习发生了」，而不是闲聊。
[Heading 2] 抓手二：把「自由闲聊」改成「结构化对话 + 检验」
每个自由对话节点，AI 手里握一张该节点必须覆盖的知识点清单（即史料切片），对话目标是「引导学生把这些点讲出来 / 接上」。改造后的对话流包含三个环节：
开场引导：AI 抛出该节点的探究主题，暗示方向。苏格拉底追问：学生命中一个知识点，点亮对应锚点；未命中，AI 用台阶式引导。节点检验：对话结束时，AI 出一道小测验题（选择 / 填空），答对才算真正过关，并计入通关评价。
这样，「学习效果」就不再是一个模糊的感受，而变成了可度量、可展示的东西——学生点亮了多少锚点、答对了几道题，一目了然。
[Heading 2] 抓手三：把「通关即结束」改成「有产出、有回顾」
这是解决「枯燥 + 无留存」的关键。每个时期结束，不再只弹一句 toast，而是生成一份学生自己的探究成果：
学习小结：一段话总结「我在这个时期弄懂了什么、触发了哪几处史料」。学生自己的感悟：一句学生自己写或选的感悟（哪怕选模板填空，也是「输出」而非「旁观」）。学习档案：进入「我的」页能看到完整档案——走过的时期、点亮的锚点、AI 给的评语。中学生一旦有了「这是我自己的成果」的拥有感，留存和复访就有了依托。

[Heading 1] 五·五、对话失控与引导兜底（核心难点）
苏格拉底式引导最大的风险，不是学生「答不上来」，而是学生不按剧本走。一个只会按理想路径引导的 AI，遇到真实的中学生很快就会失控、冷场。这一章专门定义：当对话偏离预期时，AI 如何既不失控、又不冷场地把对话拉回正轨。
[Heading 2] 5.5.1 三种典型失控场景与兜底原则
[Heading 2] 5.5.2 场景①：答不出来 → 「三级提示梯」
学生说「不知道 / 不会 / 跳过」时，AI 不要一次性把答案倒出来，而是按提示强度逐级降级：
第 1 级：换个角度追问（「你想想他七岁时写过一句什么诗？」）。第 2 级（仍答不出时）：给选择题（「他七岁写的，是关于 A.凤凰 B.白鹭 C.骏马 的？」）。第 3 级（仍答不出时）：直接给答案 + 让学生复述确认（「是凤凰，他说『开口咏凤凰』。你来说说，这能看出他什么？」）。
关键：无论走到哪一级，最后都要让学生说出一句自己的话（哪怕是复述）才算过关，保住「学习发生了」的底线。同时给 AI 加一条人设约束——绝不能因为学生答不出而责备、嘲讽、表现出不耐烦，这是面向中学生的大忌。
[Heading 2] 5.5.3 场景②：答非所问 → 「接住—关联—带回」三连
学生问了个不相干的问题（比如在「读书壮游」时期忽然问「杜甫怎么死的」），AI 不能冷冰冰说「我们先不聊这个」，那会显得机械。正确姿势是三步：
接住：先正面回应一下（「你很好奇他的结局啊。」）—— 不否定。关联：找个钩子拉回当前话题（「不过他的结局，跟他年轻时的选择其实是一脉相承的……」）。带回：落回当前知识点（「我们还是先看看他年轻时为什么到处漫游，你就懂了。」）。
关键：AI 手里始终握着一张「当前节点待办清单」，判断学生这句话能不能关联到清单里的某个点。能关联就接住展开，关联不上就走「接住—带回」。
[Heading 2] 5.5.4 场景③：提前提到后面的知识点 → 「提前点亮 + 记账」
学生一上来就说出后面才该讲的内容，处理原则是不打断、不装傻，但也不当场展开：
识别：AI 判断「这句话命中的是未来节点的知识点」。提前点亮：把对应锚点先点亮（「你已经想到这一层了，很好！」）—— 认可学生。记账：记住「这个点学生已经自己想到了，到那个节点时可以快速过、重点深挖」。
关键：这不是 bug，反而是好信号——说明学生知识储备好。AI 要能「记住」这件事（靠对话状态里的 unlocked_early 列表），到对应节点时避免重复追问、改为深入。
[Heading 2] 5.5.5 落地为「对话状态机」
三种兜底，本质都需要 AI 每次回复前先判断学生意图，再决定走哪条路。建议在云函数 chat 里加一个轻量的意图分类层（用规则 + 关键词，不必上重模型）：
每次学生输入 → 先归入四类之一：A. 命中当前节点知识点（正常引导 + 点亮锚点）；B. 答不出 / 求助（走「三级提示梯」）；C. 答非所问 / 偏离（走「接住—关联—带回」）；D. 命中未来知识点（提前点亮 + 记账，不展开）。
这个分类层是纯 Prompt 工程（在 NPC_IDENTITY 和系统指令里写清楚判定规则），成本极低，但能解决 80% 的失控。
[Heading 2] 5.5.6 其他容易翻车、但易被忽略的情况
除了上面三种，还有几类同样会让对话翻车的输入，需要一并兜底：
第一，学生恶意 / 灌水输入（刷屏、乱打字、问敏感话题）：AI 要有「不回应无关内容、温和拉回」的兜底，避免被带节奏（尤其未成年人产品，安全兜底很重要）。
第二，学生一直答对、进度飞快（学霸型）：别让对话变成机械问答，AI 要能识别「已达标」并加速推进，甚至留出「进阶追问」的空间。
第三，对话中断 / 长时间不回复（挂机）：考虑 AI 主动「还在吗」提醒，中学生容易分心。
第四，同一个知识点反复答错：说明史料本身可能超纲，需标记「该知识点难度过高」，反馈给内容团队。
第五，情绪化反馈（学生说「好难 / 不想学了」）：AI 要有鼓励 + 降低难度的情绪兜底，这是教育产品的必修课。

[Heading 1] 七、需要即刻确认的三个决策
在投入开发前，请先拍板以下三点，它们决定后续所有细节：
第一，AI 的定位：是否认同「会追问、会考察的历史老师」这个定位？（这决定史料要写成「能追问的卡片」还是「百科条目」）
第二，学习闭环的颗粒度：节点检验是「每时期一题」还是「每知识点一题」？（前者轻、后者重，影响对话节奏）
第三，产出物的形态：学习小结是「系统自动生成」还是「学生自己写 / 选」？（影响「拥有感」的强弱）

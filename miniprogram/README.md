# 寻迹·古今 —— 微信小程序

沉浸式历史文学**探究**小程序。以「史料卡 + 苏格拉底式追问」为核心机制，让 AI 化身的古人
（杜甫 / 李白）**主动追问、考察、给反馈**，引导中学生自己把历史与文学的知识点"接"出来。

> 一句话定位：学生不是来「问杜甫问题」的，而是来「被杜甫引导，完成一次历史探究」。

---

## 一、核心机制（区别于「互动小说」的地方）

| 机制 | 说明 | 代码位置 |
|---|---|---|
| **探究式对话** | AI 手里握一叠**史料卡**，用反问引导学生说出关键词；命中即点亮「知识锚点」 | `cloudfunctions/chat/engine.js` |
| **意图分类 + 三级提示梯** | 本地规则层把学生输入归为「命中 / 答不出 / 偏离 / 泛谈」四类，答不出时逐级降级：换角度追问 → 三选一台阶 → 直接讲明并请复述 | `engine.js` 的 `decideStage` / `hintLevel` |
| **考据挑战** | 每期先生故意说错**一处可核查的史实**，学生可以「捉」出来 → 先生认错、称赞、点亮专属锚点；没捉出，先生也会自己"回过神来"把正史说对（保证正确知识一定被讲到） | `line-*.js` 的 `aiFree.trap` + `pages/chat/chat.js` |
| **节点检验** | 由史料卡**动态出题**（非写死在剧本里），答完才放行「继续剧情」，每期最多 3 题 | `engine.js` 的 `pickQuiz` / `isReady` |
| **知识锚点集卡** | 命中知识点即持久化，在「我的」页可视化集卡，让"学习发生了"可度量 | `utils/progress.js` |
| **行迹地图** | 古人一生的地点按通关进度点亮，把"我走过他的人生"可视化 | `pages/map/` |
| **我的诗笺** | 每期通关生成一张可保存/分享的诗笺卡，把玩家的选择变成属于自己的产出 | `pages/poem/` |

> 「考据挑战」这一机制同时回应了评委最可能提出的质疑——**"大模型会不会编造史实？"**
> 本作品把"史实错漏"变成了要玩家去捉的东西，把风险转化为玩法本身。

## 二、技术栈

- **前端**：微信原生小程序（WXML / WXSS / JS）
- **后端**：微信云开发（云函数 + 云存储）
- **AI**：DeepSeek `deepseek-chat`（经云函数调用，Key 走环境变量）
- **内容安全**：`security.msgSecCheck` v2（用户输入与 AI 输出**双向**过滤）

## 四、如何跑起来

### 1. 配置
- `project.config.json` 的 `appid`（当前已填）
- `app.js` 的 `globalData.envId`（当前已填）

### 2. 配置 DeepSeek Key（重要）
微信开发者工具 → 云开发控制台 → 云函数 → `chat` → 配置 → 环境变量：
`DEEPSEEK_API_KEY` = `sk-xxxxxx`

> 未配置时对话走本地「人设内兜底回复」，前端链路仍可跑通（不会报错）。

### 3. 部署云函数
对 `cloudfunctions/` 下的 `login`、`chat`、`ttsUrl`、`story` 逐个右键 →
**「上传并部署：云端安装依赖」**。

> ⚠️ **改过云函数就必须重新上传部署才生效**（老坑）。
> `chat` 云函数依赖 `engine.js` / `knowledge.js` 两个本地文件，上传时**整个 `chat` 目录一起传**。

### 4. 数据库
云开发控制台 → 数据库 → 创建集合 `users`。

### 5. 本地自测（无需云环境）
```bash
node tools/test-engine.js     # 探究引擎 54 项断言
node tools/verify-story.js    # 剧本结构校验（可达性/锚点/考据挑战）
```

## 五、页面与状态说明

### 存储键（统一由 `utils/progress.js` 管理）
| key | 结构 | 用途 |
|---|---|---|
| `questStates` | `{ [主线id]: { [时期id]: 'locked'\|'active'\|'completed' } }` | 通关进度 |
| `collectedAnchors` | `{ [主线id]: { [锚点id]: true } }` | 知识锚点收集 |
| `questRecords` | `{ [主线id]: { [时期id]: {...} } }` | 探究档案（供诗笺/地图消费） |

> **已修复的 bug**：旧版 `questStates` 是扁平的 `{ p1: 'completed' }`，而杜甫线与李白线的
> 时期 id 都是 `p1..p5` —— 通关杜甫 p1 会把李白 p1 也标成已完成。现改为按主线分组，
> 并在 `progress.migrate()` 里做旧数据一次性迁移。

### 在剧本里加一处「考据挑战」
直接在某个 `aiFree` 节点上加 `trap` 字段即可（不改任何 `next` 指针，流程零风险）：
```js
n21: {
  type: 'aiFree',
  trap: {
    text: '（先生说的这句台词里藏着一处史实错漏）',
    wrong: '错的那个说法',
    right: '正确的说法',
    hint: '给学生的一点提示',
    catchText: '被捉住后先生的反应（认错 + 称赞）',
    anchor: 'a1',                       // 捉住后点亮的锚点
    toast: '考据之眼 · 捉住一处史实错漏'
  },
  prompt: '……',
  next: 'n22'
}
```

### 加一条新主线
1. 新建 `utils/stories/line-xxx.js`（照抄 `line-dufu.js` 结构）
2. 在 `utils/stories/index.js` 的 `LINES` 数组注册
3. 在 `cloudfunctions/chat/knowledge.js` 加该主线的史料卡
4. 在 `cloudfunctions/chat/engine.js` 的 `NPC_IDENTITIES` 加人设（含各时期 `era`）
5. 生成素材并上传云存储

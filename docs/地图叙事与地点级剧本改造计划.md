# 寻迹诗旅：地图叙事与地点级剧本改造计划

> 文档状态：方案确认版  
> 编制日期：2026-10-17  
> 适用范围：微信小程序 `miniprogram/`  
> 本轮目标：将叙事入口从“时期卡片”改为“人物行迹地图”，并把进度、剧本和存档粒度统一下沉到地点。
>
> 杜甫样板的逐文件实施步骤见：`docs/杜甫21地点地图叙事-开发实施步骤.md`。

## 一、已确认的产品决策

1. 地图取代现有“剧本”页，成为唯一的剧情入口。
2. 保持现有页面结构与人物选择视觉不变：启动页进入“剧本”人物选择页，选中诗人后经转场进入地图；不把人物卡牌迁到首页。
3. 现有时期级剧本已拆分为 63 个地点级剧本：杜甫 21 处、李白 20 处、苏轼 22 处。
4. 地点严格按照人物生平顺序逐个解锁；完成当前地点后，才解锁下一地点。
5. 地图地点状态统一为：
   - 未解锁：灰色；
   - 当前可进行：棕黄色，带轻微呼吸或水墨晕开动效；
   - 已完成普通地点：棕黄色常亮；
   - 已解锁的关键地点：红色；
   - 尚未解锁的关键地点：仍显示灰色，不提前暴露其重要程度。
6. 点击行为统一为：
   - 当前地点：从上次未完成的剧情节点继续；
   - 已完成地点：从该地点开头重温；
   - 未解锁地点：不可进入，只展示解锁条件。
7. 关键地点由后续提供的地点剧本确定；程序只提供 `importance` 配置和红色视觉能力，不擅自判定。
8. “好友／书童／陌生人”等玩家身份不纳入本轮开发，但本轮数据结构必须为身份分支预留接口。
9. 页面与 TabBar 暂时保持现有结构；通关结算只展示必要成果，不复用诗笺的保存相册、分享等功能。
10. 当前可进入地点继续使用“诗人头像＋向下箭头”指示，不再增加地点旁的小“行／启”字印章。
11. 保留“整页朱砂落章”作为完成仪式：可用于每集地点剧本完成后或整位诗人全线完成后；最终触发层级在视觉样片确认后决定。
12. 地图放大后的“一诗一识”暂列待定项，本轮不作为阻塞地点叙事上线的必需功能。

## 二、现状与改造原因

### 2.1 当前实现

当前产品已经具备地图页面、地点坐标、地点序号、场景图、时期进度、通关记录和云同步，但它们之间的粒度不一致：

| 模块 | 当前粒度 | 当前问题 |
|---|---|---|
| 地图展示 | 地点 | 同一时期内的多个地点会同时变为同一种状态 |
| 解锁状态 | 时期 `p1...p5` | 无法逐地点解锁 |
| 剧情脚本 | 时期 | 点击任一地点都会进入该时期开头 |
| 通关记录 | 时期 | 只能知道某一大时期完成，不能知道具体走到哪个地点 |
| 中途存档 | 无 | 离开对话页后只能重新进入该时期 |
| 诗笺与成果 | 时期 | 暂时不能直接表达逐地点旅程 |

当前代码中的地点总数是 **63 处**，而旧计划和参赛材料仍存在“43／47 处”等历史统计。后续实现、测试和材料更新均以最终地点剧本为准：杜甫 21、李白 20、苏轼 22。

### 2.2 改造后的基本单位

为避免继续混用“时期、地点、剧情节点”，改造后统一以下术语：

| 层级 | 定义 | 作用 |
|---|---|---|
| 人物线 `storyLine` | 杜甫、李白、苏轼 | 玩家在首页选择的人物旅程 |
| 时期 `period` | 读书壮游、困守长安等 | 仅用于历史分组、标题和诗笺汇总，不再直接控制解锁 |
| 地点 `location` | 泰山、长安、成都草堂等 | 地图序号、解锁和通关的基本单位 |
| 剧情节点 `node` | 旁白、对话、选择、AI 对话、反思等 | 一个地点剧本内部的最小推进单位 |
| 关键地点 `important location` | 由剧本指定的人生重大节点 | 解锁后在地图上以红色显示 |

## 三、目标用户流程

### 3.1 首次进入

1. 用户进入启动封面，完成年龄确认、协议同意和登录。
2. 启动页进入现有“剧本”人物选择页，展示杜甫、李白、苏轼卡牌。
3. 用户选择诗人后，经现有转场页进入该人物的行迹地图。
4. 地图默认聚焦序号 1：第一处地点为棕黄色可进行状态，其余地点为灰色。
5. 用户点击第一处地点，查看地点卡片并进入地点剧本。
6. 完成该地点后显示剧情结算；根据最终视觉决定是否播放一次整页朱砂落章动画。
7. 返回地图后，已完成地点常亮，通往下一地点的路线显影；下一地点由诗人头像与箭头指示。

### 3.2 再次进入

1. 用户仍从现有人物选择页选择或切换诗人。
2. 进入地图后自动聚焦当前可进行地点；从剧情通关返回时必须聚焦刚解锁的下一地点。
3. 点击当前地点后，若存在地点内存档，则从上次剧情节点继续。
4. 用户也可点击已完成地点，从该地点开头重温；重温不会清除首次通关时间和既有成果。

### 3.3 人物切换

1. 现有“剧本”人物选择页是人物选择的主入口。
2. 不同人物线的地点进度、地点内存档和成果完全隔离。
3. 切换人物不会清空原人物进度。
4. 地图页现有诗人切换能力可继续保留，页面结构不在本轮调整。

## 四、信息架构与导航约束

### 4.1 页面职责

| 页面 | 改造后职责 |
|---|---|
| 首页 `pages/index` | 启动封面、合规确认与登录，保持现有职责 |
| 剧本 `pages/story` | 保留现有诗人卡牌选择视觉，选人后进入转场和地图 |
| 行迹 `pages/map` | 当前人物的地图、地点解锁、地点卡片、剧情唯一入口 |
| 对话 `pages/chat` | 执行一个地点剧本、保存地点内节点进度、地点结算 |

| 我的 `pages/profile` | 总进度、知识锚点、清除进度、未来身份档案 |
| 原剧本页 `pages/story` | 完成迁移后退出主流程；稳定期结束再删除或保留兼容跳转 |

### 4.2 页面结构冻结

本轮不调整现有页面层级、TabBar 和人物选择视觉。开发只修改地点叙事、进度、地图完成反馈和跨页聚焦，不把导航重构混入本轮范围。

现有路径保持：

```text
启动封面 → 剧本人物选择 → 穿越转场 → 行迹地图 → 地点剧情 → 行迹地图
```

## 五、地点数据模型

### 5.1 统一地点定义

当前 `journey.js` 和各人物 `line-*.js` 对地点、场景和时期分别维护，容易出现名称、场景和顺序不一致。改造后应建立唯一的地点清单，再由地图和剧情共同消费。

建议结构：

```js
{
  id: 'dufu-taishan',          // 永久稳定 ID，不使用数组下标
  lineId: 'dufu',
  periodId: 'p1',              // 仅作历史分组
  order: 5,                    // 人生路线序号
  name: '泰山',
  range: '735年',
  x: 78,
  y: 20,
  labelPosition: 'bottom',
  sceneKey: 'taishan',
  importance: 'normal',        // normal | key；由剧本指定
  questId: 'dufu-taishan',
  unlockAfter: 'dufu-qizhao',
  summary: '登临泰山，写下《望岳》。',
  poem: '会当凌绝顶，一览众山小',
  poemTitle: '《望岳》'
}
```

规则：

- `id` 一经发布不得因改名或调整序号而变化；
- `order` 用于地图显示序号和线性解锁；
- `periodId` 只用于分组，不再作为通关主键；
- `importance` 决定已解锁后的红色表现；
- `questId` 指向对应地点剧本；
- 第一地点的 `unlockAfter` 为空，其余地点指向前一地点；
- 地图文案、诗句和地点剧本元信息不得在多个文件重复维护。

### 5.2 当前 63 地点基线

| 人物 | 时期 | 地点顺序 |
|---|---|---|
| 杜甫 | 21 地点 | 以 `docs/杜甫行迹剧本-全21地点.md` 与 `dufu-locations.js` 为准 |
| 李白 | 20 地点 | 以 `docs/李白行迹剧本-全20地点.md` 与 `libai-locations.js` 为准 |
| 苏轼 | 22 地点 | 以 `docs/苏轼行迹剧本-全22地点.md` 与 `sushi-locations.js` 为准 |

这份清单是技术基线，不代表剧情名称已经最终定稿。收到新剧本后需要逐项校验地点是否合并、拆分或更名；如需变更总数，必须同时更新地图、迁移表、测试和项目材料。

## 六、地点级剧本规范

### 6.1 一个地点就是一个可完成的小章节

每个地点剧本必须具备完整的小叙事弧，不能只把原时期剧本按场景名称机械切段。推荐结构：

1. 地点抵达：交代时间、空间和玩家为何来到这里；
2. 人物相遇：建立诗人当时的年龄、处境和关系；
3. 地点事件：只讲在此地发生或由此地触发的核心事件；
4. 玩家参与：至少一次选择、观察、追问或判断；
5. 知识落点：诗作、史实或人物变化与地点建立明确联系；
6. 地点收束：完成当地点的情感变化，并自然引向下一地点；
7. 通关结算：保存成果并解锁下一地点。

### 6.2 建议节点量

为了避免 63 个地点带来过长总时长，建议按地点等级控制：

| 地点类型 | 建议节点数 | 建议体验时长 | 必备玩法 |
|---|---:|---:|---|
| 普通过渡地点 | 6–10 | 2–4 分钟 | 旁白、对话、一次轻选择 |
| 内容地点 | 10–16 | 4–7 分钟 | 关键选择、知识锚点或诗作解释 |
| 关键地点 | 14–22 | 6–10 分钟 | 重要抉择、AI 探究或考据挑战、反思收束 |

原有 410 个节点可以作为素材池，但不要求原样保留。拆分时优先保证地点叙事完整、时间线正确和角色状态连续。

### 6.3 每份地点剧本的交付模板

后续提供剧本时，建议每个地点使用同一模板：

```md
## 地点：泰山
- locationId：dufu-taishan
- 所属时期：读书壮游
- 年代：735年
- 是否关键地点：是/否
- 玩家与诗人的当前关系：……
- 上一地点承接：……
- 下一地点引子：……
- 本地点核心事件：……
- 本地点核心问题：……
- 关联诗作：……
- 知识锚点：……
- 考据挑战：有/无
- 场景与素材需求：……
- 完整节点：n1 → n2 → …… → __end__
```

### 6.4 原时期剧本的拆分原则

1. 先按真实时间线给现有节点标注发生地点，再移动到对应地点剧本。
2. 回忆节点归到事件真实发生地，而不是当前讲述地；只有确有叙事必要时才保留闪回。
3. 一个知识锚点原则上归属一个主要地点，避免跨地点重复点亮。
4. 每个考据挑战归属最能承载该史实的关键地点，不再强制“每个时期恰好一个”。
5. AI 自由对话按关键地点配置，普通地点不强行加入，防止 63 次重复体验。
6. 地点结尾必须明确下一段旅程的动机，避免地图解锁只是机械开门。
7. 各地点开头不能假设玩家刚刚完整读完上一段长对白；需要一到两句轻量承接。

## 七、解锁、续玩与重温规则

### 7.1 地点状态

存储状态仍使用三态，视觉层再叠加“关键地点”属性：

```text
locked      未解锁，不可进入
active      当前可进行，可续玩
completed   已完成，可重温
```

状态计算规则：

1. 每条人物线只有最靠前的一个未完成地点是 `active`；
2. `active` 之前全部是 `completed`，之后全部是 `locked`；
3. 完成当前地点时，原地点写为 `completed`，下一地点写为 `active`；
4. 关键地点未解锁时仍按 `locked` 灰色显示；
5. 关键地点为 `active` 或 `completed` 时，地图标记以红色为主；当前关键地点额外增加轻微动效；
6. 重温已完成地点不会改变当前可进行地点。

### 7.2 地点内检查点

新增地点内检查点 `checkpoint`，用于“继续上次未完成的具体剧情节点”。建议字段：

```js
{
  lineId: 'dufu',
  locationId: 'dufu-taishan',
  nodeId: 'n8',
  status: 'in_progress',
  choices: [],
  anchorIds: [],
  coveredIds: [],
  quizzedIds: [],
  trapCaught: 0,
  quizCorrect: 0,
  updatedAt: 0
}
```

保存时机：

- 进入新剧情节点后；
- 玩家作出选择后；
- 完成考据挑战或知识检验后；
- AI 对话轮次完成后；
- 页面退到后台或退出前。

隐私边界：继续沿用“对话正文不上传、不落云库”的原则。云端只保存节点编号、已覆盖知识点和计数，不保存用户输入或 AI 回复原文。若用户在 AI 自由对话中途退出，恢复时回到该 AI 环节，并根据结构化进度恢复，不回放私密对话正文。

### 7.3 重温规则

- 重温从地点剧本 `start` 开始，使用临时 `replay` 会话；
- 重温过程中不覆盖首次获得时间 `earnedAt`；
- 重温产生的新锚点、考据成果可以向正式记录补充；
- 退出重温不会改变主线当前地点的检查点；
- 重温完成后返回地图原来的聚焦位置。

## 八、进度存储与兼容迁移

### 8.1 新进度结构

建议将当前按时期存储的结构升级为地点级结构，并显式加入版本号：

```js
{
  schemaVersion: 3,
  selectedLineId: 'dufu',
  locationStates: {
    dufu: {
      'dufu-gongxian': 'completed',
      'dufu-luoyang': 'active'
    }
  },
  checkpoints: {
    dufu: {
      'dufu-luoyang': { nodeId: 'n4', status: 'in_progress', updatedAt: 0 }
    }
  },
  locationRecords: {
    dufu: {
      'dufu-gongxian': { completedAt: 0, anchors: [], choices: [] }
    }
  },
  anchors: {}
}
```

时期完成度不单独存储，统一由该时期包含的地点状态推导：

- 全部地点完成：时期完成；
- 至少一处解锁但未全部完成：时期进行中；
- 第一处地点尚未解锁：时期未解锁。

### 8.2 旧进度迁移

旧用户不能因为改版丢失已通关成果。迁移规则：

1. 旧时期为 `completed`：该时期所有地点迁移为 `completed`；
2. 旧时期为 `active`：此前时期的地点全部完成，该时期第一地点设为 `active`，其余地点锁定；
3. 旧时期为 `locked`：对应地点全部锁定；
4. 旧时期通关记录保留为 `legacyPeriodRecords` 或兼容只读记录，不伪造每个地点的选择和锚点；
5. 迁移完成写入 `schemaVersion: 3`，确保幂等、只执行一次；
6. 本地迁移和云函数合并必须使用同一规则；
7. 多设备合并仍遵循“进度只增不减”，但检查点按同一地点的 `updatedAt` 取较新记录。

## 九、地图页面改造

### 9.1 页面布局

地图页建议由上到下保留四部分：

1. 人物信息：诗人姓名、旅程标题、总体进度；
2. 当前地点卡：序号、地名、所处时期、“继续旅程”按钮；
3. 地图主体：按当前人物显示 21／20／22 个地点；
4. 当前地点：使用诗人头像与箭头明确指示；
5. 已完成地点回顾：按时期分组，提供地点聚焦和重温入口。

地图页不再显示“第几程”作为主要进度，统一显示：

```text
已走过 6 / 19 处 · 当前：咸阳桥
```

时期名称可以作为地图分段标题或地点卡次级信息保留。

### 9.2 地点视觉规范

| 状态 | 圆点 | 序号章 | 地名 | 路线 |
|---|---|---|---|---|
| 未解锁 | 灰色 | 灰色 | 浅灰 | 灰色虚线 |
| 当前普通地点 | 棕黄色呼吸 | 棕黄色 | 深棕 | 通往此处的棕黄晕开线 |
| 已完成普通地点 | 棕黄色常亮 | 棕黄色 | 深棕 | 棕黄色实线 |
| 当前关键地点 | 红色呼吸 | 红色 | 深红 | 通往此处的红棕晕开线 |
| 已完成关键地点 | 红色常亮 | 红色 | 深红 | 红棕实线 |

红色只表达“人生关键地点”，不表达错误、危险或未完成。

### 9.3 当前地点指示

地图上的当前地点继续采用现有“诗人头像＋向下箭头”方案，不再增加小型文字印章。头像只负责告诉玩家下一站在哪里，不承担通关庆祝功能。

### 9.4 整页朱砂落章

保留大幅朱砂印章动画作为完成仪式，与地图地点指示分离。建议先制作同一套动效的两个触发样片，再决定最终频率：

1. **每集触发**：每完成一个地点剧本，短暂覆盖全屏 0.8–1.2 秒，印文可为“此迹已成”；
2. **全线触发**：完成一整位诗人的全部地点时，使用更完整的全屏落章与路线收束，印文按诗人定制。

推荐最终采用两级反馈：普通地点使用短促整页落章，整位诗人完成时使用独立终章大印。若真机连续体验觉得重复，再把普通地点落章缩减为关键地点触发。

### 9.5 地点卡片与待定内容

解锁地点卡片展示：序号、地点、年代、所属时期、地点简介、关联诗作、地点状态和进入按钮。

未解锁地点卡片仅展示：序号、地点名、灰度视觉和“完成第 N 处后解锁”；不展示剧情摘要、诗句和关键地点标识，避免剧透。

“一诗一识”是否进入地图页仍待定。本轮先保留现有地点卡所需数据和扩展位，不增加完整诗笺、保存相册或分享流程。若后续启用，应继续采用点击地点主动展示，不能只依赖用户手动缩放发现。

## 十、对话引擎改造

`pages/chat` 当前以 `storyId + questId(periodId)` 加载剧本。改造后入口参数统一为：

```text
/pages/chat/chat?lineId=dufu&locationId=dufu-taishan&mode=continue
```

其中：

- `mode=continue`：读取地点检查点；
- `mode=replay`：忽略正式检查点，从头重温；
- 无 `mode` 时按地点状态自动判断。

引擎需要完成以下变化：

1. 按 `locationId` 加载地点剧本；
2. 初始化时校验地点是否可进入，防止手工拼 URL 越级；
3. 在节点推进和关键交互后写入检查点；
4. 地点通关时写入地点记录并解锁下一地点；
5. 通关面板显示本地点完成摘要，并按最终决策触发整页朱砂落章；
6. 主按钮返回地图，必须把刚解锁的下一地点 ID 传给地图并自动聚焦；
7. TTS 路径逐步升级为 `audio/voice/{lineId}/{locationId}/{nodeId}.mp3`；
8. 兼容迁移期内旧的时期语音，缺失时静默回退无语音。

## 十一、诗笺、锚点与个人页联动

### 11.1 诗笺

地点仍保存选择、锚点、知识点和完成时间，供地图、个人成果与以后可能启用的“一诗一识”使用。地点通关不复用现有诗笺的保存相册、分享和完整卡片导出能力，只显示必要结算信息与完成仪式。现有诗笺页面保持当前结构，是否继续承担独立内容功能以后另行决定。

### 11.2 知识锚点

- 锚点继续按人物线全局去重；
- 每个地点记录自己触发的锚点；
- 锚点册按时期分组，在时期下标注来源地点；
- 旧锚点数据原样保留。

### 11.3 我的页面

进度展示改为人物线地点完成数，例如“杜甫 8/19”。清除进度需要同时清除地点状态、检查点、地点记录、时期汇总和未来身份选择。

## 十二、未来身份玩法预留

### 12.1 本轮只预留，不上线

未来用户可在开始一条人物线前选择身份，例如：

- 好友：与诗人已有信任，适合更直接的情感交流；
- 书童：长期随行，适合观察生活细节、承担任务；
- 陌生人：在地点偶遇，适合初识、试探和逐步建立关系。

身份不应只是称呼替换，它至少应影响：

1. 地点开场的相遇方式；
2. 诗人对玩家的信任程度；
3. 可见的选择或任务；
4. 部分对白和 AI 系统提示；
5. 跨地点的关系成长。

### 12.2 预留数据结构

本轮先保留以下字段，但默认统一为 `traveler`：

```js
runProfile: {
  lineId: 'dufu',
  identityId: 'traveler',       // 未来 friend | attendant | stranger
  relationship: 0,
  startedAt: 0
}
```

地点剧本节点允许未来增加局部变体：

```js
{
  type: 'talk',
  text: '默认台词',
  identityVariants: {
    friend: { text: '故友身份台词' },
    attendant: { text: '书童身份台词' },
    stranger: { text: '初遇身份台词' }
  }
}
```

原则是“共享主干、局部变体”，不为三个身份复制三套完整的 63 地点剧本。身份正式开发前还需单独确认：身份是整条人物线固定，还是每个时期可重选；建议整条人物线固定，重开旅程时再更换。

## 十三、实施阶段

- 标记关键地点；

- 建立旧时期节点到新地点的迁移表；
- 统计新增场景图、立绘和 TTS 需求。

**完成标准**：任意人物线都可按顺序取出地点、对应剧本、场景和下一地点。

**完成标准**：旧用户进度不丢失；新用户只能逐地点解锁；多设备同步后状态收敛。

### 阶段 3：现有入口串联核对

**完成标准**：每通关一处只解锁并聚焦下一处；下一地点由头像指示；关键地点仅在解锁后变红；完成时按规则播放整页朱砂落章。

## 十五、自动化校验与验收标准

### 15.1 数据与剧本校验

- 三条人物线地点数与总表一致；
- `order` 从 1 连续递增，无重复；
- 每个非首地点都有合法前置地点；
- 每个地点都有对应剧本且从 `start` 可达 `__end__`；
- 所有节点引用的场景、锚点和下一节点存在；
- `importance` 只能是 `normal` 或 `key`；
- 每个地点时间线不早于上一地点；
- AI 对话和考据挑战数量按剧本配置校验，不再套用“每时期恰好一个”的旧断言。

### 15.2 功能验收

1. 新用户每条人物线仅第 1 地点可进入。
2. 完成第 N 地点后，仅第 N+1 地点新增解锁。
3. 普通地点解锁后为棕黄色，关键地点解锁后为红色。
4. 未解锁关键地点仍为灰色且不显示关键标识。
5. 当前地点由诗人头像与箭头指示，不出现小型“行／启”字印章。
6. 地点剧情完成后按最终频率播放整页朱砂落章，不调用保存相册或分享。
7. 通关返回地图后自动聚焦刚解锁的下一地点。
8. 当前地点中途退出后可恢复到最近稳定节点。
9. 已完成地点可从头重温，且不会改变当前主线地点。
10. 通过手工 URL 不能进入锁定地点。
11. 切换诗人后进度不串线。
12. 旧时期进度升级后不倒退、不丢锚点和成果记录。
13. 本地与云端合并后不会把已完成地点降级。
14. 清除进度后地点状态、检查点和成果均清空，并从第 1 地点重新开始。
15. 全线完成后地图不再生成新的活动地点，并按各自剧本显示 21／20／22 地点完成文案。

### 15.3 真机体验验收

- 现有人物选择视觉在常见手机尺寸下不卡片、不遮挡；
- 地点密集区域的序号和名称仍可辨认；
- 整页朱砂落章不影响返回、后台切换和通关数据落库；
- 当前地点进入按钮单手可达；
- 地图返回、切 Tab、锁屏和小程序后台恢复不丢检查点；
- 弱网下地图底图失败仍可使用 CSS 降级层；
- 云素材或 TTS 缺失时不阻塞剧情；
- 关键地点红色与锁定灰色在低亮度屏幕上仍有足够对比度。

## 十六、主要风险与控制方式

| 风险 | 表现 | 控制方式 |
|---|---|---|
| 63 段造成内容膨胀 | 总时长过长、用户疲劳 | 普通地点短叙事，AI 探究集中在关键地点 |
| 机械切割旧剧本 | 每个地点像半截对白 | 按小叙事弧重写，结尾必须有下一站引子 |
| 地点与史实错位 | 回忆发生地和地图地点混乱 | 建立节点—地点—年代迁移表并做人工校对 |
| 旧用户进度丢失 | 改版后重新开始 | schema v3 幂等迁移，先写测试再切换页面 |
| 检查点保存过多 | 云同步频繁 | 本地立即写，云端沿用防抖上传 |
| AI 对话无法原样恢复 | 中途退出后上下文断裂 | 不保存正文，仅恢复到 AI 环节并用结构化成果重建上下文 |
| 身份预留过度设计 | 本轮复杂度失控 | 只加字段和变体接口，不写身份分支、不做身份 UI |
| 旧材料统计不一致 | 答辩或文档口径冲突 | 收尾统一更新为最终地点总数和新导航流程 |

## 十七、本轮明确不做

- 不正式上线好友、书童、陌生人三身份选择；
- 不为每个身份复制一整套剧本；
- 不引入真实地图 SDK 或定位权限；
- 不保存或上传用户与 AI 的对话正文；
- 不强制每个地点都配置 AI 对话、考据挑战或可保存诗笺；
- “一诗一识”在地图中的具体形态暂不实现，等待单独确认；
- 不在收到并审核地点剧本前擅自确定关键地点。

## 十八、开始开发前所需输入

正式进入阶段 0 前，需要按人物线提供地点剧本。允许先提供杜甫线作为样板，不必等待三条线全部完成。每个地点至少应包含：

1. 地点名称与大致年代；
2. 是否为关键地点；
3. 该地核心事件；
4. 玩家在该地要经历或完成什么；
5. 与上一地点、下一地点如何衔接；
6. 关联诗作或史实；
7. 是否需要选择、AI 对话、知识锚点、考据挑战；
8. 现有场景素材是否可复用。

收到首批剧本后，先产出“地点总表 + 旧节点迁移表 + 杜甫 p1 样板拆分”，确认体验长度和写法，再开始批量编码，可最大限度降低全量返工风险。

## 第 2 步：确认内容安全权限生效

`config.json` 已声明 `security.msgSecCheck`，但**权限要在重新部署后才生效**。

**验收点**：在对话里发一句明显违规的话，应当收到人设内的温和拒绝（"少年，这话咱们不必说……"）。

若日志里出现 `msgSecCheck 不可用，本次拦截：48001`，说明权限没生效；当前代码会失败关闭并返回预设安全回复，不会放行未经检查的内容：
- 确认 `config.json` 内容为 `{"permissions":{"openapi":["security.msgSecCheck"]}}`
- 重新上传部署 `chat`
- 若仍不行，检查小程序是否已开通该接口权限

> 代码已改为**失败关闭**：接口不可用时不展示未经检查的输入或模型输出，而是返回预设安全回复。
> 正式上线前仍必须让接口权限真正生效，否则所有自由对话都会被安全兜底替代。

### 5.7 进度云同步（换设备不丢）—— 本轮新增，需真机验

> 这一段只能真机验，模拟器不便换设备。请用**两台设备/两个微信号**，或"删掉小程序重进"来模拟。

- [ ] **上传**：通关一个时期 → 等 3 秒（防抖 2.5s）→ 云开发控制台 → 数据库 → `users` →
      该用户记录的 `progress` 字段里应能看到 `states` / `anchors` / `records` 三层数据
- [ ] **拉取合并**：换一台设备（或用另一个微信）用同一账号进入 → 「剧本」页应显示**已通关状态**
- [ ] **不降级**：明明云上有 `completed`，本地是 `active` 时拉取后应变回 `completed`
      （合并规则是取较优，绝不降级）
- [ ] **重新开始要连云端一起清**：点「清除进度，重新开始」→ 杀掉小程序重进 →
      进度**不应**被云端数据"复活"（这条最容易踩坑：服务端合并是"只增不减"的，
      所以必须走 `clearState`，不能用空快照 `saveState` 代替）
- [ ] **断网不崩**：关掉网络进入小程序 → 不报错、不卡死，进度仍能正常玩（本地缓存兜底），
      恢复网络后下次变更会把进度补传上去

> 若云端 `progress` 一直是空：多半是 `story` 云函数没上传，或 `users` 集合不存在。
> 看 Console 里的 `[sync]` 前缀警告即可定位（**它只会警告，不会影响本地使用**）。

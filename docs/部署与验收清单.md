# 部署与验收清单（本轮改造后必做）

> 本轮改造动了云函数、页面、存储结构三处，**不是"编译一下就能跑"**。
> 按下面顺序做，每步都有验收点。全部做完约 30–45 分钟。

---

## 第 0 步：先跑本地自测（不用开发者工具，1 分钟）

在项目根目录执行：

```bash
node tools/test-engine.js      # 探究引擎 54 项断言
node tools/verify-story.js     # 剧本结构（可达性/锚点/考据挑战）
node tools/check-wxml-data.js   # 页面字段引用一致性
```

**通过标准**：三条都输出 `ALL PASS` / `ALL_OK` / `ALL CLEAR`。
若第一条就失败，先别往下走——说明 `knowledge.js` 或 `engine.js` 有问题。

---

## 第 1 步：上传 `chat` 云函数（**最关键**）

本轮 `chat` 云函数从 1 个文件变成 4 个：

```
cloudfunctions/chat/
├── index.js       云侧外壳（内容安全 + DeepSeek + 降级）
├── engine.js      ★ 新增：探究引擎纯逻辑
├── knowledge.js   ★ 新增：史料卡知识库（49 张）
└── config.json    ★ 已改：声明 security.msgSecCheck 权限
```

**操作**：开发者工具 → 资源管理器 → `cloudfunctions/chat` 右键 →
**「上传并部署：云端安装依赖（不上传 node_modules）」**

**验收点**：
- [ ] 云开发控制台 → 云函数 → `chat` → 代码里能看到 `engine.js` 和 `knowledge.js`
- [ ] `chat` 的「配置」里 `DEEPSEEK_API_KEY` 仍在（重新部署有时会清掉环境变量，务必确认）
- [ ] 云开发控制台 → 云函数 → `chat` → 日志：调用一次后能看到 `[chat]` 前缀日志

> ⚠️ 忘了这步 = 前端所有新机制（探究/考据/检验）都不会生效，且可能因找不到
> `./engine`、`./knowledge` 直接报错。

## 第 2 步：确认内容安全权限生效

`config.json` 已声明 `security.msgSecCheck`，但**权限要在重新部署后才生效**。

**验收点**：在对话里发一句明显违规的话，应当收到人设内的温和拒绝（"少年，这话咱们不必说……"）。

若日志里出现 `msgSecCheck 不可用，本次放行：48001`，说明权限没生效：
- 确认 `config.json` 内容为 `{"permissions":{"openapi":["security.msgSecCheck"]}}`
- 重新上传部署 `chat`
- 若仍不行，检查小程序是否已开通该接口权限

> 代码里做了**降级放行**：接口不可用时不会让对话整个挂掉，只是没有过滤。
> 体验版可以先这样，**正式上线前必须让它真正生效**。

## 第 4 步：（可选但强烈建议）做一张行迹地图底图

行迹地图页**在没有底图时也能正常运行**（纯 CSS 示意布局，不会空白、不会报错）。
但有一张水墨底图，演示效果好得多。

**要做就做这一件事**：用 ImageGen 生成一张**竖版**中国水墨地图，
上传到云存储 `assets/images/map/map-china.jpg`（路径必须一致，代码已指向这里）。

可直接用的 prompt：

```
一张极简中国水墨风格的地图底图，竖版构图，宣纸米黄底（#f5f0e8）。
只用水墨线条勾勒中国轮廓与主要水系（黄河、长江），淡墨远山做点缀。
不标注任何地名、文字、现代边界线、经纬网格。整体留白充分、色调温暖素雅，
适合作为交互式地图的底图，方便在上面叠加地点标记。
底部不要任何水印、文字、logo。
```

生成后：裁掉底部水印 → 转 JPG → 上传云存储 `assets/images/map/` 目录 →
清缓存编译 → 进行迹页验收。

## 第 5 步：编译并逐页验收

开发者工具 → **清缓存（全部清除）** → 编译。

### 5.1 首页
- [ ] 封面视频正常播放，背景音乐在点「开始穿越之旅」后响起
- [ ] 穿越动画（水墨 + 卷轴）正常

### 5.2 剧本页
- [ ] 三条线显示：杜甫 / 李白 可玩，苏轼「敬请期待」
- [ ] **重点验收串号 bug 已修**：通关杜甫「读书壮游」后返回，
      再进李白线——**李白的「仗剑出蜀」不应显示为已通关**
      （旧版两者都用 `p1` 做 key，会互相污染）

### 5.3 对话页 —— 本轮改动最集中，逐项验
- [ ] 右上角有常驻 **「AI 生成」** 标识
- [ ] 台词打字机效果正常，「点击继续 ›」可推进
- [ ] 带「决定性瞬间」的选项有对/错反馈

**考据挑战**（每期自由对话开始时触发）：
- [ ] 进入自由对话，先生先开口说一句台词，下面出现
      「⟡ 先生此言，你听着可有不对之处？」+ 两个按钮
- [ ] 点 **「这里不对！」** → 先生认错+"考据之眼"toast + 点亮锚点 + 出现"继续请教"
- [ ] 点 **「接着听」** → 先生自己回过神来把正史说对（**必须验这条**：
      没捉出来也要看到正确知识，这是"内容准确"的保障）

**探究式对话**：
- [ ] 头部显示「AI」徽标 + 「与杜甫当面请教 · 已探究 N 处史料」
- [ ] 说中史料卡关键词 → 顶部弹「触发知识锚点：XXX」+ 计数增加
- [ ] 说「我不知道」→ 先生换成更具体的角度追问（第一级提示）
- [ ] 连续说两次「不知道」→ 先生给"三选一"小台阶（第二级）
- [ ] 连续三次 → 先生直接讲明并请复述（第三级）
- [ ] 问一个不相干的问题 → 先生先接住、再关联、再带回（不生硬拒绝）
- [ ] 探究到 3 处以上 → 出现 **「✦ 先生考校」** 检验题
- [ ] 答完检验题后「▶ 继续剧情」才可点（未答时应不可点）
- [ ] 同一期最多出 3 道题，不会无限出

**通关收束**：
- [ ] 面板显示锚点数 + **考据之眼：捉出 N/M 处史实错漏** + 先生考校得分

## 已知遗留（不影响参赛，记录备查）

| 项 | 说明 |
|---|---|
| AI 回复非真流式 | 当前是"云函数返回完整回复 + 前端模拟逐字"，体感接近流式；真流式需迁云托管 SSE |
| 进度仅本地存储 | `questRecords`/`questStates` 都在 `wx.setStorageSync`，换设备会丢；落云数据库是上线前的事 |
| `story` 云函数是预留 | 前端进度不走它（走 `utils/progress.js`），未部署也不影响运行 |
| 立绘无表情差分 | `trap`/`choice` 等状态复用同一张时期立绘 |
| 苏轼线未做 | 「敬请期待」占位（评分表明确不以功能数量论高低，把两条线做深更划算） |

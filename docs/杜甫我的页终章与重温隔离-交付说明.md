## 一、「我的」页实际文案

卡片标题：**杜甫线 · 我的角色**

| 状态 | 判定 | 显示 | 操作按钮 |
| --- | --- | --- | --- |
| 未创建 | 无档案 | 「尚未创建角色」 | 创建角色 › |
| 迁移草稿 | `confirmed:false` | 姓名 + 外观名（如「寻迹者 / 形象二」） | 确认角色 › |
| 已确认 | `confirmed:true` | 姓名 + 外观名 + 立绘缩略图 | 编辑 › |
| 档案损坏 | 存储里有但不合法 | 朱色「角色资料需修复」 | 修复角色 › |

卡片底部说明（常驻）：**剧情中的名字 · 与账号昵称无关，不影响学习进度**

账号昵称仍在页首原有区域（点头像或昵称可改），与角色卡互不影响。

「重新开始」确认文案（已含角色）：

> 将清除全部旅程进度、知识锚点、诗笺记录与杜甫角色资料，并从第一程重新出发。账号和昵称不会受到影响。确定吗？

清除成功后立即调用 `refreshRoleCard()`，角色卡回到「尚未创建」——不再显示已删除的角色。

## 二、终章实际文案

地点收束面板在原有「已走过 / 诗名 / 知识点 / 锚点 / 考校」之后新增回望区：

```
同行者回望（示例，全线通关后）

同行者：小杜
在一次次重逢中，你见过——
· 洛阳的东厢房里，你第一次见他——七岁的孩子写下「开口咏凤凰」
· 泰山的台阶望不到顶，他在山巅写下「会当凌绝顶，一览众山小」
· 长安陷落，他困在城里写「国破山河在，城春草木深」
· 夔州高处，他写下「无边落木萧萧下，不尽长江滚滚来」
· 湘江的孤舟上，他说「飘飘何所似，天地一沙鸥」
```

重温时的回望区：

```
同行者：小杜
这一段是回望。风景还在原处，你的正式旅程与诗笺都没有被改写。
```

约束落实：

- 只用**全体玩家必经事件**（22 条，与 AI 记忆同一源 `memory.js`）。
- 时序为「在一次次重逢中」，不写几十年肉身伴随；不出现「一直陪」。
- 不按 `avatarId` 推断性别/职业/性格；三种外观得到**完全相同**的终章正文（测试 4.5 断言）。
- 不写「因为你/你救/你改变」，不把玩家写成改变杜甫命运的人（4.8 断言）。
- 姓名只出现在 UI 文本，**不进入任何配音**；NPC 固定台词不念动态姓名。
- 李白、苏轼线回望为空数组，结算面板保持原样。

地图「当前行迹」卡片（不新增常驻组件）：

```
行  当前行迹  同行者：小杜
    洛阳 · 七岁咏凤凰
    约719年
                              进入此地 ›
```

同期 `全程已完成` 卡片也带同一行「同行者」。李白/苏轼恒不显示（`companionName` 对非角色线返回空）。

## 三、重温读写隔离清单

| 数据 | replay 行为 | 实现位置 |
| --- | --- | --- |
| 地点检查点 `locationCheckpoints` | 不写 | `gotoNode` / `onHide` 经 `_shouldWriteProgress()` |
| 地点状态 `locationStates` | 不写（完成/解锁均不写） | `onLocationEnd` 守卫内才 `completeLocation` |
| 诗笺记录 `locationRecords` | 不写（通关时间不改） | `onLocationEnd` 守卫 |
| 关键选择 / 选项结果 | 不落盘，仅内存展示 | 只进 `data.choices`，随页面销毁丢弃 |
| 知识锚点 `collectedAnchors` | 不写（仅在内存点亮） | `fireAnchor` / `showAnchorCardNode` 守卫 |
| 任务步骤 / 见证物 | 不写 | 剧本已无 tasks；写入 API 未被调用且路径受同一守卫 |
| 期通关 `questStates` + `questRecords` | 不写（时期模式另加只读分支） | `onQuestEnd` 守卫 |
| 角色档案 `playerProfiles` | 不写 | chat 页本就不写角色（只读恢复） |
| 通关时间 / 诗笺奖励 | 保持不变 | 同上 |
| AI 聊天记录 | 仅本次内存，退出即丢弃 | `chatLog` 每进 aiFree 重置 + `sessionId` 含地点 |
| AI 可用记忆 | 按回放地点截断 | `memory.resolveAvailableEvents` |
| 地图聚焦 `mapFocus` | 不写 | `_applyMapFocusOnReturn` 提前 return |

统一入口：`_shouldWriteProgress()` → `playMode.shouldPersist(mode)`；`playMode.isReplay(mode)`。
chat.js 中已无裸 `_mode === 'replay'` 判断（测试 6.12 断言）。

### 新增的可测纯模块

| 文件 | 作用 |
| --- | --- |
| `utils/play-mode.js` | `isReplay` / `shouldPersist` / `resolveStartNode`（重温恒 start，正式才读检查点） |
| `utils/player-card.js` | 四态判定 `resolveRoleCard` + 地图同行者 `companionName` |
| `utils/dufu-recap.js` | 终章回望 `buildRecap` / `shouldShowRecap` |
| `utils/dufu-events.js` | **自动生成**：22 条必经事件 + 回望文案（源为 `memory.js`） |

## 六、需实机确认的布局项

1. 「我的」页角色卡在 iPhone SE 级小屏：4 种状态下文字不换行溢出，「修复角色」朱色可辨识。
2. 地图「当前行迹」卡多出「同行者：姓名」后：一行是否仍单行显示；长名（8 个字）是否挤压「进入此地」。
3. 终章收束面板：5 条回望 + 原有锚点列表 + 底部按钮，在小屏是否需滚动（卡片已设 `max-height:86vh` + `overflow-y:auto`）。
4. 重温收束只 2 行时，面板高度与按钮位置是否协调。
5. 编辑角色保存后返回「我的」页，缩略图是否立即刷新（`onShow` 已刷新；云图首次可能先显示剪影再淡入）。

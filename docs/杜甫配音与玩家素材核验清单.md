## 一、配音路径修复说明

### 1.1 修复前的实际缺陷

地点入口的 URL 只有 `locationId`、没有 `questId`（`/pages/chat/chat?storyId=dufu&locationId=taishan&mode=continue`）。
`onLoad` 早期执行：

```js
const questId = options.questId || '';   // 地点模式 → 空串
this._ttsQuestId = questId;              // → 空串
```

而 `playNodeAudio` 的守卫是 `if (!this._ttsQuestId) return;`。
结论：**地点模式下配音从未请求过**，不是"路径写错"，而是整条链路在守卫处就返回了。

### 1.2 修复方式

| 项目 | 修复前 | 修复后 |
| --- | --- | --- |
| 音频分组 id | `_ttsQuestId = options.questId`（地点模式为空） | `_audioQuestId = locationMode ? locationId : questId`，在**剧本加载完成后**确定 |
| 类型守卫 | 只判断 `speaker === 'npc'`（在调用点） | `voiceTarget.isNpcTalkNode(node)`：必须 `type === 'talk'` 且 `speaker` 缺省或 `npc` |
| 迟到链接 | 比较 `request`/`nodeId`（内联在页面里） | 抽到 `voiceTarget.shouldAcceptAudioResult()`，页面与测试共用 |
| 切到非说话节点 | 上一句 NPC 语音继续播 | 作废在途请求并 `stop()` |
| 文本一致性 | 无 | 与清单摘要比对，不一致跳过旧音频并打日志 |
| 缓存键 | `storyId/questId/nodeId` | `storyId/audioQuestId/nodeId#文本摘要` |

音频键规则（与 `utils/ttsAudio.js` 一致）：

```
地点模式：audio/voice/{lineId}/{locationId}/{nodeId}.mp3   → dufu/taishan/n2a.mp3
时期模式：audio/voice/{lineId}/{periodId}/{nodeId}.mp3     → libai/p2/n3.mp3   （保持不变）
```

## 二、更新后的导出用法

```bash
# 杜甫 22 地点（第一版唯一启用地点配音的线）
node tools/export-voice-manifest.js

# 单地点（分段录制时用）
node tools/export-voice-manifest.js --line=dufu --location=taishan

# 三线全部（李白/苏轼若日后也改地点配音）
node tools/export-voice-manifest.js --all

# 旧时期兼容：只写 dufu-p1.json，不碰运行时摘要表与报告
node tools/export-voice-manifest.js dufu p1

# 只重算报告与运行时摘要，不写清单
node tools/export-voice-manifest.js --report-only
```

产物：

| 文件 | 内容 |
| --- | --- |
| `tts-audio/manifests/dufu-locations.json` | 22 地点总清单：每条含 `lineId / kind / audioQuestId / nodeId / emotion / text / digest / fileName / cloudPath` |

## 三、需重做音频清单（结论）

| 分类 | 数量 | 说明 |
| --- | --- | --- |
| 需要录入 | **407** | 地点模式全部 NPC talk 节点；`audio/voice/dufu/<location>/<node>.mp3` 尚未有任何文件 |
| 可复用 | **0** | 旧音频在 `audio/voice/dufu/p1..p4/`，属已废弃的时期剧本，节点 id 与文本均不对应 |
| 无 NPC 配音 | **447** | 旁白 296 / 选项 91 / 知识卡 21 / 讲述 22 / AI 自由对话 17 |

「可复用 0」是**预期结论、不是缺口**：旧音频按时期路径录制（`audio/voice/dufu/pN/`），
地点模式的音频键是 `audio/voice/dufu/<location>/`。音频键不同即不是同一份文件，
旧音频不会被"复用"到新路径下，也不需要人工逐条比对是否可复用。

### 旧音频处置（待删资产）

| 资产 | 位置 | 状态 |
| --- | --- | --- |
| 旧时期 mp3（杜甫 79 条） | `tts-audio/output/dufu/p1..p4/` | 待删除 |
| 旧时期清单（含 emotion-plan） | `tts-audio/manifests/dufu-p*.json` | 兼容期保留，不参与复用判定 |

`_cloud_upload/audio/` 下只有 bgm，没有 `voice/` 副本——旧配音从未按云端 voice 路径上传。
因此地点模式不存在"云端残留旧文件被误播"的风险。

**运行时对应行为是「跳过」，不是「降级复用」**：文本摘要与清单不一致时
`utils/ttsAudio.js` 直接返回空串（这一句无配音），剧情照常文字推进。
这是最终设计——文本与配音必须严格一致，宁可这一句没有声音，也不让少年听到与屏幕上不同的台词；
任何"容忍旧音频继续播放"的降级都不应再加回来。

明细见 `tts-audio/manifests/voice-report.md`（逐节点云端路径 + 情绪 + 原因）。

## 一、发布顺序（必须按此顺序）

### 阶段 1：先部署兼容新字段的云函数（客户端可选旧）

| 顺序 | 云函数 | 本次改动 | 为什么必须先部署 |
| --- | --- | --- | --- |
| 1 | `story` | 新增 `playerProfiles` 合并、`emptySnapshot()` 含角色空对象、`saveState` 返回权威快照 | 旧客户端上传不带 `playerProfiles` 的快照时，服务端必须**保留**已存角色；先部署才能不丢数据 |
| 2 | `chat` | 新增 `memory.js` / `scenes.js` / `fallback.js`；读 `users` 集合的 `locationStates.dufu` 作为可信进度；白名单可信 prompt 替代客户端 `freePrompt` | 旧客户端仍会传 `freePrompt` 与 `playerRoleId`，新服务端**忽略**它们即可正常工作；反之新客户端打到旧服务端会缺少共同经历（不报错，只是记忆变少） |

**两个云函数都必须重新上传并部署**（改云函数不部署等于没改）。

部署后自检：

- `chat` 云函数日志出现 `[chat] 读取云端进度失败，降级为客户端本地进度` → 说明 `users` 集合读取有问题（权限/集合名），需要排查；这条降级不会阻塞对话。
- 日志出现 `[chat] 未知锚点已忽略` 或 `[tts] 文本与语音清单不一致，已跳过旧音频（需重录）` → 属预期保护行为，不是故障。

## 二、回退方法

### 客户端回退（推荐，风险最低）

1. 微信公众平台 → 版本管理 → 回退到上一线上版本。
2. **保留服务端新增 `playerProfiles` 字段**——旧客户端不认识该字段，但服务端合并会保留它，回退后用户数据不丢。
3. 回退后**不要**清空 `users` 集合。

### 只关闭新入口（不完全回退）

| 目标 | 做法 | 影响 |
| --- | --- | --- |
| 关闭角色创建入口 | `utils/player-guard.js` 的 `ROLE_LINES` 改为 `[]` | 所有入口不再跳角色页；已有角色仍能在聊天页恢复显示 |
| 关闭 AI 共同经历 | `cloudfunctions/chat/index.js` 中跳过 `availableMemories` 计算 | AI 退回「无记忆」语气，不报错 |
| 关闭地点配音 | `utils/voice-target.js` 的 `resolveAudioQuestId` 返回空串 | 全部静音，文字照常 |
| 关闭终章回望 | `utils/dufu-recap.js` 的 `shouldShowRecap` 返回 false | 收束面板无回望区 |

### 回退严禁事项

- ❌ 不得清空 `playerProfiles`（会丢用户角色）
- ❌ 不得把 `avatarId` 当旧职业 `roleId` 回写（数据语义不同）
- ❌ 不得删除 `locationProfiles` 与 `locationStates`（会丢学习进度）
- ❌ 不得删除 `audio/voice/` 下新录的音频（回退后可复用）

## 三、逐处文本改动与配音影响

“影响配音”表示预设旁白或角色台词已变化，需要在后续配音步骤重新导出对应清单；仅 AI 场景 Prompt 和编辑规范不影响预录音频。

### 全线规范

- 旧：每个地点都要有“又是你”式重逢钩子，玩家是“一路相随”的同路人。
- 新：玩家是在关键人生节点与杜甫重逢的同一位同行者；首站真初见，后续可重逢、继续同行或安静照面，不填满两站之间的全部岁月；称呼不与外观绑定。
- 原因：统一“关键节点穿越重逢”的设定，避免机械重复和持续随侍误读。
- 影响配音：否。

### `luoyang`

- `n1a`
  - 旧：“今日杜家宴客，你是随家里长辈一同登门的小客人……”
  - 新：“今日杜家宴客，院门未闭。你从席间走到东厢房外……这是你第一次来到这里，也将是你与杜甫的初见。”
  - 原因：删除玩家家世和年龄背景，建立真正初见。
  - 影响配音：是。
- `n2a`
  - 旧：“可是今日随府上大人一同登门的客人？”
  - 新：“看着面生，可是今日来府上的客人？”
  - 原因：杜甫可以判断玩家是客人，但不替玩家编造随行长辈。
  - 影响配音：是。
- `n7.prompt`
  - 旧：玩家“随家里人在洛阳杜家做客”。
  - 新：玩家“初到洛阳杜家，第一次与七八岁的杜甫在书房对坐”，并明确不得谈后来共同经历。
  - 原因：约束自由对话知识边界。
  - 影响配音：否。

## 六、补充：动作型选项显式标记（2026-10-22，步骤十验收阶段）

步骤五为解析器加了 `actionOnly` / `spokenText` 数据语义，但当时约定“不在该步骤批量改 22 地点正文”，因此数据未标记，呈现仍走旧的「括号文本当台词」回退。步骤十验收 C 组要求“玩家对白、动作呈现正确”，据此在本轮补齐标记。

### 判定规则（不使用脆弱的括号文本猜测）

以「选项文本里括号之后是否还有正文」为唯一判据：

- 括号后仍有正文 → 玩家确实说了那句话（如「（问）这山，爬上去要多久？」）→ 保持 talk；
- 整个选项就是一个括号、括号外没有字（如「（沉默地听着）」「（望着山下的天地，没说话）」）→ 只有动作、没有可念的台词 → 标 `actionOnly: true`。

不采用“括号内是否含‘说’字”之类的字面规则：实测会误判「（望着那山，**没说话**）」「（什么也不**说**，陪他站着）」等 18 条纯动作项。

### 改动量与结果

- 标记 **119 条**（22 地点合计 259 个选项中的纯动作项）。
- 其余 **140 条**（括号后有正文 110 + 无括号 30）保持 talk。
- 源稿只新增 `actionOnly: true` 一处标记：去掉该标记后与改前源稿**逐字节一致**，正文一字未改。
- 节点数仍 **854**（未增删节点），`build-dufu-locations --check`、`verify-location-story`、`verify-locations` 全部通过。
- 配音清单不受影响（选项从不进配音）：仍 407 条 NPC 台词。
- 运行时行为：`playerChoiceNode` 对 119 条生成 `action` 节点（以旁白/动作行居中呈现，无姓名、玩家立绘不登场说话），其余生成玩家 `talk` 节点。

### 影响配音

否。动作型选项本来就不属于 NPC 台词，也不会被朗读。

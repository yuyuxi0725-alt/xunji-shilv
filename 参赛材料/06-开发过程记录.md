## 二、关键设计决策（含被推翻的方案）

### 2.1 从"知识问答"到"探究引导"——本项目最重要的一次转向

**动因**：团队在 2026-10-01 复盘时确认了三个病灶：① AI 对话形同虚设（每期仅 3–4 条示例史料，
学生问两三个问题就词穷）；② 台词虽是"看台词 → 选选项 → 继续看"的线性推进，学生全程是被动观众；
③ 通关只弹一句数字，没有检验、没有产出。

**结论**：产品当前是"**能看完的互动小说**"，而不是"**能让人学进去、还想回来的探究产品**"。
根源是同一个——**把 AI 当成了"回答机器"，而不是"会追问、会考察、会给反馈的历史老师"**。

**这次转向直接产出了参赛版本的核心机制**：史料卡作为知识底座、意图分类、三级提示梯、
动态节点检验，以及最具辨识度的"考据挑战"。

### 2.2 被推翻的方案（如实记录）

| 方案 | 推翻原因 | 替代方案 |
|---|---|---|
| 用第三方字体（行书 / 霞鹜文楷）做古风标题 | 团队评估后认为"错落手书"观感不佳，且增加体积与授权风险 | **全部弃用第三方字体，统一系统楷体字族**（STKaiti/KaiTi/FangSong） |
| TTS 插件实时合成语音 | 被小程序**主体资质**卡死（插件需相应类目） | 预生成 TTS 音频包上传云存储，前端只播音频（零插件、零资质、零 API Key） |
| 穿越转场用 VideoGen 生成视频 | 真机上出现**平台水印**，视频无法像图片那样裁掉 | 改为**纯 CSS 动画**（水墨晕染 + 卷轴展开），零水印、零加载延迟 |
| 背景音乐只在穿越期间播放 | 用户反馈"音乐很快就没了" | 改为**全局常驻**（`app.js` 单例 + 渐入渐出 + 可关闭开关） |
| 同期铺开第三条线（苏轼） | 评分标准明确"不以技术复杂度、代码规模或功能数量作为统一评价依据" | **集中做深杜甫、李白两条线**，苏轼保留"敬请期待"占位 |
| 立绘在结尾"完整讲述"时上移避让文字 | 多次调整仍显局促 | 结尾**隐去立绘**，纯深黑幕 + 逐句文字，更沉浸有回味 |

### 2.3 李白线的"区分度"问题与纠偏

**问题**：团队反馈"李白线和杜甫线光看剧情都一样，没区分度"，"体验完杜甫没感觉到杜甫的底色"。

**诊断**：两条线都按"人生阶段"横切，骨架雷同，换个名字能套；杜甫的底色是"讲"出来的
（结尾旁白总结），而非被玩家"逼"出来的（玩家没被迫做那个选择）。

**方案与纠偏**：先提出"区分宪法"（杜甫＝仁·韧·史，李白＝狂·仙·逸），但团队随即纠偏——
**"不必刻意对比李杜，最终目的只是让古人形象更立体"**。据此把重心从"对比"转向"各自立住"：
李白线五期重新设计，每期给一个与人物底色强绑定的决定性瞬间（如 p5"永王来请：避祸还是入幕"
——**选"对"的一步反而酿成悲剧**，点出李白最想入世却总摔最重的悲剧性）。

### 2.4 考据挑战的由来

**动因**：团队预判评委必问"**大模型会不会编造史实？**"。常规做法是加免责声明，但这既被动、
又无法证伪。

**方案**：反过来把风险做成玩法——**每期让先生故意说错一处可核查的史实，等学生来捉**。
- 学生捉出 → 先生认错、称赞、点亮专属锚点（正反馈）
- 学生没捉出 → 先生**自己"回过神来"把正史说对**（保证正确知识一定被讲到，也避免错误表述
  残留在 AI 的对话上下文里被沿用）

**实现细节上的取舍**：trap 字段**挂在每期已有的 `aiFree`（自由请教）节点上，不改动任何
`next` 指针**——剧本 255 个节点的主流程零风险，且考据挑战天然成为自由对话的开场引子。

## 三、过程中解决的关键技术问题（工程能力证据）

### 3.1 DeepSeek 接入：三层叠加故障

首次接入时对话不通，逐层排查发现是**三个问题叠加**：
① 云函数未上传部署；② API Key 未配置到云函数环境变量（而非硬编码）；③ 模型名/接口路径笔误。
**沉淀经验**：改云函数后必须重新上传部署才生效。

### 3.2 语音无声：从"插件方案"到"云函数代取临时链接"

- 现象：TTS 音频报"文件不存在"，但控制台里能看见文件。
- 根因：**微信云开发免费版存储权限锁定「仅创建者可读写」，且控制台不允许修改**，
  端上直接读云文件会报 `STORAGE_EXCEED_AUTHORITY`。
- 方案：改用**云函数（管理端权限）代取临时链接**（新增 `ttsUrl` 云函数），
  前端把临时链接缓存到全局跨页面复用。此方案后来复用于封面视频、BGM 与全部场景图。

### 3.3 真机包体 2MB 超限

- 现象：模拟器编译正常，真机调试报"代码包大小 11956 KB，上限 2048 KB"。
- 诊断：11.7MB 中 **11.6MB 是图片**，代码只有 0.2MB。
- 方案：大图全部迁云存储，新增 `utils/cloudAssets.js`（批量换临时链接 + 进程内缓存 +
  深度路径替换）；包体降到 156KB。
- **连锁坑**：图片迁走后编译仍报 `ENOENT ... open 'miniprogram/assets/images/npc/xxx.png'`
  ——微信编译器会扫描 JS 里的 `/assets/images/...` **路径字面量**当静态资源打包。
  解法：所有本地图片路径改为**运行时拼接**，规避编译期静态收集，运行时行为不变。

### 3.4 云函数 20s 硬上限（-504003）

- 现象：AI 回复偶发超时，学生看到报错。
- 方案：内部超时 11–12s、`max_tokens` 压缩、历史仅取最近 6 轮、Prompt 紧凑；
  超时/失败一律用**人设内兜底回复**（用户无感降级，绝不回错误文案）。

### 3.5 AI 回答"串线"（问李白答杜甫）

- 根因：云函数的人设与知识库都写死为杜甫，李白线的自由对话拿到的 System Prompt
  还是"你是杜甫"。
- 方案：云函数改造为**多 NPC 可配置**（`NPC_IDENTITIES` + 分 NPC 知识库），
  前端透传 `npcId`。

### 3.6 多主线进度互相污染（参赛改造版修复）

- 根因：进度存成扁平的 `{ p1: 'completed' }`，而**杜甫线与李白线的时期 id 都是 `p1..p5`**
  ——通关杜甫 p1 会把李白 p1 也标成已完成。
- 方案：新建 `utils/progress.js` 统一存储层，全部状态改为**按主线分组**的二级结构，
  并提供旧数据一次性迁移；剧本页、对话页、"我的"页三处全部改走它。

### 3.7 其他已修复问题（择要）

- 立绘被全屏背景层盖住（`z-index` 层级踩坑）→ 建立层级规则并写入代码注释
- 结尾"完整讲述"立绘压住文字 → 改为隐去立绘
- `story.wxml` 行内样式含 `{{}}` 触发 CSS 校验器误报 → 定位为开发者工具已知问题，
  通过改文件语言模式解决
- 音乐无声（异步时序 bug）：点击"开始穿越"时临时链接尚未取回，`ensureBgm` 直接 return，
  而这**是唯一的手势时机，错过就再也不响** → 重构为"链接未就绪则等待取回后再播"

| 四期见面逻辑 | 见面场景前后矛盾 | 明确为"p1 泰山初见 → p2 长安重逢 → p3 沦陷长安再会 → p4 成都草堂" |
| 李白线语气去雷同 | "开头自我介绍/结尾问句全和杜甫雷同，感觉在经历同一个人的人生" | 逐句改写为李白式狂放自报家门 |
| 史实校对 | 自检发现年份矛盾 | 修正《春望》年份链；修正"自长安一别转眼又是十年"（p2 覆盖 746–755 整十年，p3 是 756，说"十年"不成立） |

47 张场景图、11 张立绘、TTS 台词语音包、49 张史料卡、36 个知识锚点。

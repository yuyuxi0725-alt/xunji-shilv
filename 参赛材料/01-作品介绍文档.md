## 〇、作品基本信息

| 项目 | 内容 |
|---|---|
| 作品名称 | 寻迹·古今 |
| 一句话定位 | 让中学生「被古代诗人亲自引导着做一次历史探究」的沉浸式古诗文学习小程序 |
| 目标用户 | 12–18 岁中学生，兼顾语文／历史教师与研学机构 |
| 承载终端 | 微信小程序（体验版），后端为微信云开发 |
| 核心内容 | 杜甫线 4 期 114 节点、李白线 5 期 141 节点，共 255 个剧情节点；49 张史料卡 |
| 人工智能 | DeepSeek `deepseek-chat` 驱动角色对话；图像、语音素材由生成式人工智能辅助生产 |

学生穿越到唐朝，成为与杜甫、李白萍水相逢的「少年同游者」，走完他们的人生；在每个时期被这位诗人追问、考察，甚至要抓出他故意说错的一处史实；最终带着自己点亮的「知识锚点」、一张诗笺与一段人生行迹离开。

## 一、选题价值与导向（10 分）

### 1.1 问题意识：背得出，不等于读得懂

中学生背《春望》不超过三分钟，默写可以满分；但若追问「他为什么在春天看见花开反而流泪」，多数人只能复述教辅结论，说不出「至德二载春、身陷叛军占据的长安、妻儿远在鄜州」这些具体处境。断层不在学生，而在**现有学习载体不承载「理解」**：课本与讲解视频给的是结论而非得出结论的过程，题库把古诗文压缩成可判对错的选项，短片再生动，学生也只是"看过"，没有一次属于自己的判断。本项目要回答的问题因此很具体：**能否让学生不只是「读」完杜甫，而是被杜甫本人引导着亲手完成一次历史探究？**

### 1.2 目标用户、场景与选题规模

主用户为 12–18 岁中学生：已有基本古诗文阅读能力与历史常识，但抽象概括能力尚在发展，最需要「具体处境＋可参与的判断」，故全文采用浅近文言味的白话、单段台词控制在 60–150 字。次用户为语文／历史教师与研学、博物馆机构；场景为课后自主探究（主场景，单期 10–20 分钟）、课堂导入、研学行前预习与行后回顾。评分标准明确"不以技术复杂度、代码规模或功能数量作为统一评价依据"，本项目据此集中做深两条人物主线，放弃同期铺开第三条线（苏轼线保留「敬请期待」占位）。

### 1.3 与赛项的契合

赛项要求创作**内容准确、表达生动**、具有时代特征和传播价值的中国故事。**内容准确**：剧情文本依据中学教材共识与《旧唐书》《新唐书》杜甫传、杜甫自述诗、仇兆鳌《杜诗详注》、冯至《杜甫传》等交叉核验；学术有争议处一律回避，或在知识库中逐条标注"一说／有争议"的说明。**表达生动**：47 张水墨工笔场景图、11 张分时期立绘、打字机文本、场景交叉淡入、回忆闪回慢转场、全局古风配乐。**时代特征**：以大模型承担"会追问的历史老师"角色。而"内容准确"恰是本项目最有力的一处设计——我们把大模型"可能编造史实"这一公认风险，转化为产品内的核心玩法（见 2.3）。

## 二、创新性与原创贡献（25 分）

### 2.1 一句话创新定位

> 既有产品把 AI 当成"更聪明的回答机器"，我们把 AI 变成了**一位会追问、会考察、甚至会故意说错话的历史老师**。

### 2.2 创新点一：AI 从「回答机器」升级为「会追问、会考察的历史老师」（已完成，运行中）

"AI＋古诗文"产品的通行范式是：学生提问 → AI 给一段准确的百科式答案。这实际把学习降级为检索——学生得到结论，绕过的恰是"理解"。本项目反过来：**AI 手里握着一叠史料卡，不急着给答案，而是先追问。**

学生问"您七岁就写诗了吗"，杜甫不答"对"，而反问："我杜家祖上，也出过一位武后朝的大诗人，你可知是谁？我的诗才，与他又有什么渊源？"学生说出"杜审言"，AI 真诚肯定并推进；答不出，则换一个更小的台阶引导。**先把学生自己的话逼出来，再补全知识。**

该机制由三层实现：**史料卡知识库**（49 张结构化卡片，杜甫线 24、李白线 25，每张含 id／title／content／引导反问／关键词／锚点／检验题，全部由团队撰写核验；AI 的回答被严格约束在史料之内，史料之外宁可表示"不知"也不编造）；**探究引擎**（不依赖云环境、可单元测试的纯逻辑层，把学生输入归类为四种意图——命中知识点／答不出求助／答非所问／泛泛而谈，再据此注入八种本轮指令）；**三级提示梯**（答不出时逐级降级：换角度追问 → 给"三选一"小台阶 → 温和讲明并请复述，并在提示词中写明底线"绝不能因少年答不出而责备、嘲讽或表现出不耐烦"）。

上述意图分类、八种本轮指令、提示梯降级规则、双 NPC 人设（杜甫"沉郁温厚"、李白"豪放飘逸"）的异同刻画、知识边界规则（只了解自己所处时期及之前的事、不预知未来）、人设禁区与互动原则，全部由团队构思撰写并反复迭代。

### 2.3 创新点二：「考据挑战」——把大模型的史实风险转化为玩法机制（**已完成并运行**）

**机制。** 每个时期设 1 处"错漏点"，两条线共 **9 处**（杜甫 4、李白 5）：**AI 会故意说错一处可核查的史实，由玩家把它抓出来。** 例如：杜甫说"我七岁那年，咏的是白鹭"（实为"开口咏凤凰"，出自《壮游》）；说"《春望》作于至德元载春"（实为至德二载春，757 年）；说"《登高》是成都草堂所作"（实作于夔州）；李白把与杜甫初见之地记错（实为洛阳）；把永王说成"奉太子之命"（实为玄宗之子、肃宗之弟，卷入帝位之争）。

**玩家体验。** 进入自由对话时先生说一句含错漏的话，界面随即出现"⟡ 先生此言，你听着可有不对之处？"与两个按钮：点**「这里不对！」**→ 先生认错、真心称赞，点亮一枚**专属锚点**，弹出"考据之眼"战果；点**「接着听」**→ 先生自己"回过神来"把正史说对——**保证"内容准确"在任何路径下都守得住**，且不做任何惩罚。

**为什么这是全篇最具辨识度的一笔。** 第一，**这是只有 AI 才能实现的玩法**：脚本可以预设"选错选项"，却无法回应"玩家用自己的话自由指出错误"，这从机制层面证明"AI 是玩法本身，而非装饰"。第二，**它把行业最大的风险变成了产品最大的亮点**：评审看到"AI 讲历史"，第一反应必然是"大模型会不会胡说"；常规做法是防御，我们选择进攻——**既然幻觉无法根除，就把它请到台前，让玩家来抓**。若被问及"AI 会不会编造史实"，我们的回答是："我们把幻觉做成了游戏机制，玩家在本产品里最重要的能力，就是抓住 AI 说的假话。"第三，**它训练的是真正的核心素养**：抓住一处史实错误需要先记住正确史实、再比对、再输出判断，恰好对应历史学科"史料实证"与批判性思维的要求，也直接服务赛项"内容准确"这一硬指标。第四，**它对剧本零风险**：错漏以字段挂在自由对话节点上，不改变任何节点指针与剧情分支。

### 2.4 创新点三：「知识锚点」——把学习过程变成可度量的收集物（已完成，运行中）

学习效果最难度量，因为它看不见。本项目把每个关键知识点固化为一枚**知识锚点**：学生在对话中说出史料卡的关键词、或在剧情中抵达关键史实节点时，锚点被点亮，屏幕浮出"✦ 触发知识锚点：壮游与《望岳》"。全篇共 36 枚（杜甫 16、李白 20）。锚点有三重视觉与心理反馈：对话页顶部常驻"已点亮／总数"计数、点亮瞬间的 toast、「我的」页一张集卡式锚点表（已点亮亮棕 ✦、未点亮灰色 ·）；通关时展示"这一程，你触发了 X/Y 个知识锚点"并逐条列出，附上"考据之眼：捉出 N/M 处史实错漏"与"先生考校：答对 N 题"的战绩。由此，"读完一段故事"被转化为"我在这段故事里弄懂了哪几件事"，学习过程第一次**可计数、可回顾、可展示**；对 12–18 岁用户而言收集行为天然具备驱动力，"学完"于是变成了"集齐"。

### 2.5 创新点四：AI 原生的产出物「我的诗笺」与「行迹地图」（**已完成并运行**）

**我的诗笺**：每期通关后生成一张竖排诗笺卡（朱印落款），内容包括昵称、走过的时期与年代、**你在关键抉择处的实际选择**、点亮的锚点、考据之眼与先生考校的战绩、一句该时期的代表诗句，以及一句依你的抉择给出的评语；可导出保存到相册、可一键复制分享。它把玩家从"观众"变成"输出者"——玩完之后学生手里握着的是"我的诗笺，上面写着我替他做的选择"，既是产品最直接的传播载体，也是答辩现场最有说服力的展示物。

**行迹地图**：已作为底部第四个标签页「行迹」。一张中国水墨地图标注杜甫、李白一生的行经地点（**杜甫 15 处、李白 16 处**）。每通关一期，对应路线以水墨晕开方式点亮一段；已通关地点点亮、当前时期闪动、未解锁置灰；点击地点弹出古风卡片，写明该地发生的事、相关诗作与注解（未走到的地方不剧透）。地图与诗笺可互相跳转，同时是研学／文旅场景的接口；**无底图时自动降级为纯 CSS 示意山河，不空白、不报错**。

### 2.6 与既有成果的实质差异（评分标准明确要求）

| 既有成果形态 | 本项目的实质差异 |
|---|---|
| **互动小说／视觉小说** | 既有成果中玩家在**预设分支**中选择、系统给固定反馈，无论怎么选都不改变"AI 讲什么"；本项目选项只是骨架，**真正的交互发生在 AI 自由对话中**——玩家说中关键词、答不出、跑题，AI 分别作出肯定、逐级给台阶、接住再带回。玩家不是挑一个写好的答案，而是**生成一段只属于他自己的对话** |
| **知识问答／闯关答题类 App** | 既有成果判对错、给分数、排榜单；本项目不设分数与排名，答不出走三级提示梯，最终以"说出一句自己的话"过关，AI 是**引导者而非裁判**；检验题由史料卡动态生成、每期最多 3 道 |
| **课本剧／历史情景剧短视频** | 既有成果是单向观看，学生不参与判断；本项目把"判断"交给玩家——主动发问、**抓出先生故意说错的史实**、在关键抉择处替诗人拿主意，观看时间被替换为**决策时间** |
| **通用大模型问答** | 既有成果无角色、无年代感、无知识边界、易被诱导离题，对未成年人无内容安全约束；本项目为每个 NPC 建立**人设、知识边界、人设禁区与史料依据**，输入与输出**双向过微信内容安全接口**，并对越界、灌水、情绪化输入设定人设内的温和兜底 |

**一句话概括**：既有成果让学生"看一个关于诗人的故事"或"查一个关于诗人的答案"，本项目让学生"**和这位诗人一起走一段路，并在此过程中被反复追问，甚至还要纠他的错**"。

### 2.7 学生团队的原创构思与关键贡献

①**玩法范式判断**：从"AI 是回答机器"到"AI 是追问者与考察者"的范式转变，及由此推导的四项机制，是最核心的原创构思。②**叙事设计**：确立"玩家＝穿越到唐朝的少年同游者"的角色定位，据此定下四条语言规则——对话用第一人称、关键抉择用"若你是我，你会怎么选"、旁白克制只交代场景、结尾"同游者回望"绝不点破"底色/品质"等标签词，**"底色"二字永远不出现在角色口中，必须由学生自己在心里冒出来**。③**双线的「区分宪法」**：先以一句话锁死两人的灵魂内核（杜甫＝仁·韧·史，放不下天下；李白＝狂·仙·逸，绝不低头），再让剧情、九个决定性瞬间与九段结尾回望全部围绕这一内核展开，形成**两条方向相反的灵魂弧线**；李白线 p5 更采用反讽设计——**"正确"的选择（入幕报国）反而导致悲剧**。④**史料考据与结构化**：自行完成史料查找、交叉核验与 49 张史料卡的撰写，争议年份一律以中学教材共识为准、存疑处逐条标注。⑤**开发与整合**：前端六大页面、多主线架构、探究引擎、云函数、数据存储层、自动化校验脚本与 AIGC 素材后处理全部由团队完成。

**三个关键架构决策（团队自主判断）。** ①**多主线注册表架构**：每条人物线独立成一个数据文件，注册表只做注册与查询，**新增一条线只需新建数据文件、注册表加一行、补史料卡与人设、生成素材，页面与引擎零改动**，项目由此从"一条线的小程序"演进为可扩展的古人系列产品。②**探究引擎与云侧外壳拆分**：意图分类、提示梯、命中检测、出题与提示词组装全部放进不依赖云环境的 `engine.js`，从而**可离线跑自动化断言**（54 项），这正是评分标准要求的"过程、测试和关键结论可核验"。③**大图全部迁移云存储＋云函数代取链接**：主包上限 2MB 而场景图与立绘合计约 11.6MB，真机调试直接报"代码包大小 11956kb，上限 2048kb"；又因免费套餐存储权限锁死为"仅创建者可读写"，前端取临时链接被拒（`STORAGE_EXCEED_AUTHORITY`），团队遂将大图迁入云存储并改用**云函数代取临时链接**、配进程内缓存与自动分批。此外 Key 只存云函数环境变量，用户侧仅以 openid 作匿名标识。

### 3.2 视觉小说与探究对话引擎（核心交互实现）

五类节点（旁白／对话／抉择／自由对话／结尾回望）由统一引擎调度，节点以 `next` 串联、抉择选项可带独立分支。已实现的关键交互：**打字机**（60ms/字，点击立即显示全文、再点才推进）；**场景交叉淡入**（双图层叠加，常规 1.1s，回忆闪回用 1.8s 慢速转场，形成"思绪飘回过去 → 回到现实"的时间线感）；**立绘显隐与分期面孔**（按节点类型自动显隐并可被节点级配置覆盖；杜甫 p1 青年 20 岁、p2 中年 38 岁、p3 沧桑 45 岁、p4 苍老 55 岁）；**抉择反馈**（决定性瞬间给"✦ 正确／○ 需再想"轻量反馈后推进，并记入探究档案）；**考据挑战面板**；**节点检验面板**（"✦ 先生考校"，答完才放行"继续剧情"）；**AI 生成内容标识**（对话页右上角常驻「AI 生成」角标，自由对话面板另有「AI」徽标与"已探究 N 处史料"提示）；**结尾回望演出**（逐句浮现 2s/句，纯深黑背景居中）；**通关收束面板**（朱印"通"字＋宣纸卡片弹入）；**AI 回复的流式观感**（云端返回后前端以 40ms/字逐字填充，按 Unicode 码点拆分保证中文与 emoji 不错位）。

层级规则已固化为项目规范：立绘必须位于背景层与暗角层之上、对话框之下。团队在开发中曾因给双层背景加 `z-index` 而未给立绘设层级，导致立绘被整层遮盖，该问题已修复并写入项目长期记忆。

### 3.3 AIGC 素材生产管线与人工干预环节

美术与语音素材大量借助生成式人工智能生产，但每项成果都经过人工筛选、返工、重绘、抠图、压缩与集成（完整清单见《人工智能工具使用情况说明》）。统一管线为：团队撰写含画风、构图、色调与年代约束的提示词 → 生成候选图 → 目视筛选（不合格直接废弃重生成）→ 裁除平台水印（场景图裁底部 95px、封面图裁底部 80px）→ 立绘抠图（四边中位数估背景色 → BFS 洪泛填充 → 保留含中心种子的最大连通域 → alpha 羽化 → 量化 256 色）→ 尺寸格式统一（场景 1024×1441 竖版 JPG；立绘 1024×1536 PNG 透明通道）→ 深浅双背景目检 → 上传云存储 → 代码集成。全部素材的平台水印均已清除，作品不含任何第三方水印。

**三例真实的人工返工（可现场展示前后对比）。** ①**杜甫 p2 立绘两次返工**：首版被判定"灰白胡子像六七十岁"（该时期实际 35–44 岁）且单色素描风与前期彩色工笔断档，重生成后又被判定"躬身低头像乞丐"、与"落魄但有风骨"的人物判断不符，第三版在提示词中明确写入"腰背挺直、头微抬、目光沉郁坚定望向远方""旧袍微有磨损"才通过——此案例沉淀为团队经验：人物立绘提示词必须明确姿态，负面意象会被模型放大。②**视频转场因平台水印被整体弃用**：真机测试发现生成视频的平台水印无法像图片那样裁除，最终放弃视频方案、改为纯 CSS 水墨晕染＋卷轴展开动画。③**封面视频的无缝循环改造**：视频模型无法完成"推近再拉回"的往返运动（实测首尾帧差异单调递增至 21.9%），团队改用"正放＋倒放拼接"把首尾差异从 8.3% 降至 1.38%，得到 24.79 秒的无缝循环封面。

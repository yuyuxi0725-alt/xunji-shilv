## 〇、作品基本信息

| 项目 | 内容 |
|---|---|
| 作品名称 | 寻迹·古今 |
| 一句话定位 | 让中学生「被古代诗人亲自引导着做一次历史探究」的沉浸式古诗文学习小程序 |
| 目标用户 | 12–18 岁中学生，兼顾语文／历史教师与研学机构 |
| 承载终端 | 微信小程序（体验版），后端为微信云开发 |
| 核心内容 | 杜甫线 4 期 114 节点、李白线 5 期 141 节点，共 255 个剧情节点 |
| 人工智能 | DeepSeek `deepseek-chat` 驱动角色对话；图像、语音素材由生成式人工智能辅助生产 |

学生穿越到唐朝，成为与杜甫、李白萍水相逢的「少年同游者」，走完他们的人生，在每个时期被这位诗人追问、反问、检验，最终带着自己点亮的「知识锚点」与一段人生行迹离开。

## 一、选题价值与导向（10 分）

### 1.1 问题意识：背得出，不等于读得懂

中学生背《春望》不超过三分钟，默写可以满分；但若追问「他为什么在春天看见花开反而流泪」，多数人只能复述教辅结论，说不出「至德二载春、身陷叛军占据的长安、妻儿远在鄜州」这些具体处境。断层不在学生，而在**现有学习载体不承载「理解」**：课本与讲解视频给的是结论而非得出结论的过程，题库把古诗文压缩成可判对错的选项，科普短片再生动，学生也只是"看过"，没有一次属于自己的判断。本项目要回答的问题因此很具体：**能否让学生不只是「读」完杜甫，而是被杜甫本人引导着亲手完成一次历史探究？**

### 1.2 目标用户、场景与选题规模

主用户为 12–18 岁中学生：已有基本古诗文阅读能力与历史常识，但抽象概括能力尚在发展，最需要「具体处境＋可参与的判断」，故全文采用浅近文言味的白话、单段台词控制在 60–150 字；次用户为语文／历史教师与研学、博物馆机构；场景为课后自主探究（主场景，单期 10–20 分钟）、课堂导入、研学行前预习与行后回顾。评分标准明确"不以技术复杂度、代码规模或功能数量作为统一评价依据"，本项目据此集中做深两条人物主线，放弃同期铺开第三条线（苏轼线保留「敬请期待」占位）。

### 1.3 与赛项的契合

赛项要求创作**内容准确、表达生动**、具有时代特征和传播价值的中国故事。**内容准确**：剧情文本依据中学教材共识与《旧唐书》《新唐书》杜甫传、杜甫自述诗、仇兆鳌《杜诗详注》、冯至《杜甫传》等交叉核验，学术有争议处（李白出生地、《蜀道难》作年、高力士脱靴真伪）一律回避或改用"传说"口吻，不写入知识点。**表达生动**：47 张水墨工笔场景图、11 张分时期立绘、打字机文本、场景交叉淡入、回忆闪回慢转场、全局古风配乐。**时代特征**：以大模型承担"会追问的历史老师"角色。而"内容准确"恰是本项目最有力的一处设计——我们把大模型"可能编造史实"这一公认风险，转化为产品内的核心玩法（见 2.3）。

## 二、创新性与原创贡献（25 分）

### 2.1 一句话创新定位

> 既有产品把 AI 当成"更聪明的回答机器"，我们把 AI 变成了**一位会追问、会考察、甚至会故意说错话的历史老师**。

### 2.2 创新点一：AI 从「回答机器」升级为「会追问的历史老师」（已完成，运行中）

"AI＋古诗文"产品的通行范式是：学生提问 → AI 给一段准确的百科式答案。这实际把学习降级为检索——学生得到结论，绕过的恰是"理解"。本项目反过来：**AI 不急着给答案，而是先追问。** 学生问"您七岁就写诗了吗"，杜甫不答"对"，而反问："我杜家祖上，也出过一位武后朝的大诗人，你可知是谁？我的诗才，与他又有什么渊源？"学生说出"杜审言"，AI 真诚肯定并推进；答不出，则换一个更小的台阶引导。**先把学生自己的话逼出来，再补全知识。**

该理念已落地于 `cloudfunctions/chat/index.js` 的系统提示词，含三组约束：**①互动原则**——先回应少年刚说的话再作答，每段回复结尾必须抛回一个话头，一次只讲一个要点，回复 60–150 字，以纠正大模型"自说自话灌输知识点"的讲课感；**②【追问心法（苏格拉底式）】**——学生给出看法后先顺他的话追问"为什么这样想""你从哪一句看出来的"，追问要轻、要短，答不出时立刻放下、换更简单的话头；**③【人设禁区】**——禁用现代词与网络用语，不得直接抛出"标准答案"式总结，不得用括号心理描写或表情符号。上述规则、双 NPC 人设（杜甫"沉郁温厚"、李白"豪放飘逸"）的异同刻画、知识边界规则（"只了解自己所处时期及之前的事，不预知未来"）与"是什么 → 为什么 → 你怎么看"的提问梯度，全部由团队构思撰写并反复迭代。

### 2.3 创新点二：「考据挑战」——把大模型的史实风险转化为玩法机制（设计完成并列入实施计划，见 4.3）

**机制。** 每个时期设 1–2 处"错漏点"：**AI 会故意说错一处史实，由玩家把它抓出来。** 例如杜甫回忆少年时"说错"——"我七岁那年，咏的是白鹭。"（史实为"开口咏凤凰"，出自杜甫《壮游》"七龄思即壮，开口咏凤凰"）。玩家指出错误，杜甫"愣住，随即抚掌大笑：好眼力！"，点亮一枚稀有锚点并记入探究档案；玩家未抓住，则由杜甫自己"回过神来"纠正，**不做任何惩罚**。

**为什么这是全篇最具辨识度的一笔。**

第一，**这是只有 AI 才能实现的玩法**：脚本可以预设"选错选项"，却无法回应"玩家用自己的话自由指出错误"——能否抓住、用什么措辞指出是完全开放的输入，这从机制层面证明"AI 是玩法本身，而非装饰"。

第二，**它把行业最大的风险变成了产品最大的亮点**：评审看到"AI 讲历史"，第一反应必然是"大模型会不会胡说"；常规做法是防御（加知识库、加校验、加免责声明），我们选择进攻——**既然幻觉无法根除，就把它请到台前，让玩家来抓**。若被问及"AI 会不会编造史实"，我们的回答是："我们把幻觉做成了游戏机制，玩家在本产品里最重要的能力，就是抓住 AI 说的假话。"

第三，**它训练的是真正的核心素养**：抓住一处史实错误需要先记住正确史实、再比对、再输出判断，恰好对应历史学科"史料实证"与批判性思维的要求，也直接服务赛项"内容准确"这一硬指标。

第四，**实现成本可控**：史料卡新增一个 `trap` 字段（记录错误表述与正确史实）、系统提示词新增一条指令、前端新增一处反馈动画即可。

**实现状态（如实说明）。** 机制设计已完成，数据层已预留字段（`utils/progress.js` 探究档案中的 `trapCaught`、`trapTotal`）；**剧情节点的 `trap` 标记与云函数对应指令尚未实现**，已列入校内提交前的实施计划。若提交时仍未完成，材料与演示视频一律按"设计完成、开发中"标注，不做展示性演示。

### 2.4 创新点三：「知识锚点」——把学习过程变成可度量的收集物（已完成，运行中）

学习效果最难度量，因为它看不见。本项目把每个关键知识点固化为一枚**知识锚点**：玩家抵达关键史实节点时锚点被点亮，屏幕浮出"✦ 触发知识锚点：壮游与《望岳》"。全篇共 36 枚（杜甫 16、李白 20），逐一对应具体史实与名篇。锚点有三重视觉与心理反馈：对话页顶部常驻"已点亮／总数"计数、点亮瞬间的 toast 提示、「我的」页一张集卡式锚点表（已点亮亮棕 ✦、未点亮灰色 ·）；通关时展示"这一程，你触发了 X/Y 个知识锚点"并逐条列出。由此，"读完一段故事"被转化为"我在这段故事里弄懂了哪几件事"，学习过程第一次**可计数、可回顾、可展示**；对 12–18 岁用户而言收集行为天然具备驱动力，"学完"于是变成了"集齐"。

### 2.5 创新点四：AI 原生的产出物「我的诗笺」与「行迹地图」（数据层已预留，页面开发中，见 4.3）

**我的诗笺**：每期通关后生成一张竖版诗笺卡——玩家昵称、走过的时期、点亮的锚点清单、关键抉择处的实际选择记录，以及**依据玩家选择生成的一句诗**，可保存相册、可分享。它把玩家从"观众"变成"输出者"：玩完之后学生手里握着的不是"我看过一个故事"，而是"这是我的诗笺，上面写着我替他做的选择"，既是产品最直接的传播载体，也是答辩现场最有说服力的展示物。

**行迹地图**：一张中国水墨地图标注杜甫、李白一生行经之地（洛阳、长安、泰山、鄜州、成都、夔州、湘江；江油、峨眉、荆门、终南山、浔阳、当涂等），每通关一期即以水墨晕开方式点亮一段，点击可看该地发生的事与相关诗作，把"知识"变成"走过的路"，也是研学与文旅场景的天然接口。

**实现状态**：底层数据层已完成——`utils/progress.js` 探究档案已预定义通关时间、点亮的锚点 id 与中文名、锚点总数、关键选择记录 `choices`、决定性瞬间结果 `keyChoice`、生成诗句字段 `poem`；**两个页面尚未开发。**

### 2.6 与既有成果的实质差异（评分标准明确要求）

| 既有成果形态 | 本项目的实质差异 |
|---|---|
| **互动小说／视觉小说** | 既有成果中玩家在**预设分支**中选择、系统给固定反馈，无论怎么选都不改变"AI 讲什么"；本项目选项只是骨架，**真正的交互发生在 AI 自由对话中**——玩家用自然语言表达理解，AI 依据玩家实际说出的话决定肯定、追问、换台阶还是提前点亮，玩家不是挑一个写好的答案，而是**生成一段只属于他自己的对话** |
| **知识问答／闯关答题类 App** | 既有成果判对错、给分数、排榜单，强化记忆检索；本项目不设分数与排名，答不出走三级提示梯，最终以"说出一句自己的话"过关，AI 是**引导者而非裁判** |
| **课本剧／历史情景剧短视频** | 既有成果是单向观看，学生不参与判断；本项目把"判断"交给玩家——主动提问、抓出 AI 的错话、在关键抉择处替诗人拿主意，观看时间被替换为**决策时间** |
| **通用大模型问答** | 既有成果无角色、无年代感、无知识边界、易被诱导离题；本项目为每个 NPC 建立**人设、知识边界、人设禁区与史料依据**，史料之外宁可说"不知"也不编造，并对越界、灌水、情绪化输入设定兜底 |

**一句话概括**：既有成果让学生"看一个关于诗人的故事"或"查一个关于诗人的答案"，本项目让学生"**和这位诗人一起走一段路，并在此过程中被反复追问**"。

### 2.7 学生团队的原创构思与关键贡献

①**玩法范式判断**：从"AI 是回答机器"到"AI 是追问者与考察者"的范式转变及由此推导的四项机制，是最核心的原创构思。②**叙事设计**：确立"玩家＝穿越到唐朝的少年同游者"的角色定位，据此定下四条语言规则——对话用第一人称、关键抉择用"若你是我，你会怎么选"、旁白克制只交代场景、结尾"同游者回望"绝不点破"底色/品质"等标签词，**"底色"二字永远不出现在角色口中，必须由学生自己在心里冒出来**。③**双线的「区分宪法」**：先以一句话锁死两人的灵魂内核（杜甫＝仁·韧·史，放不下天下；李白＝狂·仙·逸，绝不低头），再让剧情、九个决定性瞬间与九段结尾回望全部围绕这一内核展开，形成**两条方向相反的灵魂弧线**，其中李白线 p5 更采用反讽设计——**"正确"的选择（入幕报国）反而导致悲剧**。④**史料考据与结构化**：自行完成史料查找、交叉核验与结构化（首期 8 张七字段史料卡），争议年份一律以中学教材共识为准。⑤**开发与整合**：前端引擎、多主线架构、云函数、数据存储层、AIGC 素材后处理与集成全部由团队完成。

**两个关键架构决策（团队自主判断）。** ①**多主线注册表架构**：每条人物线独立成一个数据文件（只含 `periods / quests / scenes / sceneSets / npcImage / periodNpcImages / anchors` 七项），注册表只做注册与查询，**新增一条人物线只需新建数据文件、注册表加一行、生成素材三步，页面与引擎零改动**，项目由此从"一条线的小程序"演进为"可扩展的古人系列产品"。②**大图全部迁移云存储＋云函数代取链接**：主包上限 2MB 而场景图与立绘合计约 11.6MB，真机调试直接报"代码包大小 11956kb，上限 2048kb"；又因免费套餐存储权限锁死为"仅创建者可读写"且控制台不允许修改，前端取临时链接被拒（`STORAGE_EXCEED_AUTHORITY`），团队遂将大图迁入云存储（本地包体降至 156KB）并改用**云函数代取临时链接**、配进程内缓存与自动分批——整套方案是在真实报错中排查出来的，非套用模板。此外 DeepSeek Key 只存云函数环境变量，用户侧仅以 openid 作匿名标识，不采集手机号、姓名与位置。

### 3.2 视觉小说引擎（核心交互实现）

五类节点（`narrate` 旁白／`talk` 对话／`choice` 抉择／`aiFree` 自由对话／`reflect` 结尾回望）由统一引擎调度，节点以 `next` 串联、抉择选项可带独立分支。已实现的关键交互：**打字机**（60ms/字，点击立即显示全文、再点才推进，避免快速点击跳过内容）；**场景交叉淡入**（双图层叠加，常规 1.1s，回忆闪回用 1.8s 慢速转场，形成"思绪飘回过去 → 回到现实"的时间线感）；**立绘显隐与分期面孔**（按节点类型自动显隐并可由节点级 `npc:true/false` 覆盖，统一使用该时期基准面孔——杜甫 p1 青年 20 岁、p2 中年 38 岁、p3 沧桑 45 岁、p4 苍老 55 岁）；**抉择反馈**（决定性瞬间显示"⚖ 关键抉择"标签，选择后给"✦ 正确／○ 需再想"轻量反馈再推进分支）；**结尾回望演出**（逐句浮现 2s/句，隐去立绘、纯深黑背景居中）；**通关收束面板**（朱印"通"字＋宣纸卡片弹入，展示本期锚点清单）；**AI 回复的流式观感**（云端返回后前端以 40ms/字逐字填充气泡，按 Unicode 码点拆分使中文与 emoji 不错位）。层级规则已固化为项目规范：立绘必须位于背景层与暗角层之上、对话框之下。

### 3.3 AIGC 素材生产管线与人工干预环节

美术与语音素材大量借助生成式人工智能生产，但每项成果都经过人工筛选、返工、重绘、抠图、压缩与集成（完整清单见《人工智能工具使用情况说明》）。统一管线为：团队撰写含画风、构图、色调与年代约束的 prompt → 生成候选图 → 目视筛选（不合格直接废弃重生成）→ 裁除平台水印（场景图裁底部 95px、封面图裁底部 80px）→ 立绘抠图（四边中位数估背景色 → BFS 洪泛填充 → 保留含中心种子的最大连通域 → alpha 羽化 → 量化 256 色）→ 尺寸格式统一（场景 1024×1441 竖版 JPG；立绘 1024×1536 PNG 透明通道）→ 深／浅双背景目检 → 上传云存储 → 代码集成。全部素材的平台水印均已清除，作品不含任何第三方水印。

**三例真实的人工返工（可现场展示前后对比）。** ①**杜甫 p2 立绘两次返工**：首版被判定"灰白胡子像六七十岁"（该时期实际 35–44 岁）且单色素描风与前期彩色工笔断档，重生成后又被判定"躬身低头像乞丐"、与"落魄但有风骨"的人物判断不符，第三版在提示词中明确写入"腰背挺直、头微抬、目光沉郁坚定望向远方""旧袍微有磨损"才通过——此案例沉淀为团队经验：人物立绘提示词必须明确姿态，负面意象会被模型放大。②**视频转场因平台水印被整体弃用**：真机测试发现生成视频的平台水印无法像图片那样裁除，最终放弃视频方案、改为纯 CSS 水墨晕染＋卷轴展开动画。③**封面视频的无缝循环改造**：视频模型无法完成"推近再拉回"的往返运动（实测首尾帧差异单调递增至 21.9%），团队改用"正放＋倒放拼接"把首尾差异从 8.3% 降至 1.38%，得到 24.79 秒的无缝循环封面。

## 五、应用与传播价值（10 分）

**应用场景**：①课堂导入——讲《春望》《望岳》《茅屋为秋风所破歌》《行路难》前用 5–10 分钟演示对应时期，让学生先"认识写诗的人"再读诗；②课后自主探究——获得锚点清单与（规划中的）诗笺，把课后作业从抄写刷题转为一次有产出的探究；③研学与博物馆——与"重走杜甫入蜀路""唐诗之路"等线路结合，行前预习、行中对照、行后回顾，行迹地图为天然接口；④家庭亲子共读——围绕 9 个决定性瞬间讨论"你会怎么选"。

**文化传播价值**：对象精准，面向即将形成文化认同的 12–18 岁人群，这一年龄段建立的对诗人的亲近感会长期影响其后对传统文化的态度；方式适配微信生态，零安装、可分享、可扫码，通关产出物自带分享动机，不设排行榜与分数以免把文化学习异化为竞争；立场端正，不戏说、不魔改、不强行"网络化"古诗文，AI 被明确禁止使用现代词与网络用语，同时坚持不点破品质标签，把价值判断的权利留给学生自己完成。

**后续规划**：近期（提交后至总决赛）完成考据挑战、节点检验、三级提示梯，上线「我的诗笺」与「行迹地图」，替换背景音乐为授权明确曲目，补齐内容安全与 AI 标识等合规项，推进备案与主体流程；中期扩充结构化史料卡至全量、按人物线补充苏轼等新主线（架构已支持）；长期把行迹地图扩展为可实际行走的研学线路，并探索把"考据挑战"做成可自主配置的题型。产品的核心资产是**"AI 作为追问者"这一交互范式与两条人物线的叙事内容**，具备长期可迭代性。
